# 후보 Model Card — SECOM S0·M3 Top-20

> 후속 사용자 요청으로 이 모델을 활성 경로에서 제외했다. 묶음은 복구 가능한 `models/retired/v1_m3_sensor20/`로 이동했으며 아래 내용은 V1 실험 이력이다. 현재 V2 모델은 [V2 Model Card](model_card_v2.md)로 구분한다.

작성 기준일: 2026-10-07. 상태: **연구·데모 평가 대상 동결·후속 평가 완료, 정책 목표 미달, 현장 배포 미승인**.

## 1. 목적과 현재 상태

SECOM의 수치형 공정 센서로 불량 의심 대상을 선별하는 연구·데모용 이진 분류 모델이다. 입력 센서를 20개로 제한하고, 학습과 독립적인 저장·복원·CSV 추론 경로를 보여주는 것이 현재 산출물의 목적이다.

- 학습 후보: 전체 과거 Time Train + S0 RF 센서 선택 + M3 XGBoost.
- 보존 비교 후보: S2 선택기, M0 분류기. 이 카드의 저장 묶음에는 포함하지 않는다.
- 산출물: `models/candidates/m3_sensor20/candidate.joblib`, 같은 폴더의 `manifest.json`.
- 저장 상태: `is_final_model=false`를 유지한다. 후속 사용자 승인으로 이 저장 후보의 센서 목록·통계·모델·문턱을 연구·데모 평가 대상으로 동결했다. 현장 배포 모델로 전환한 것은 아니다.
- 시간순 검증에서 불량 탐지 정책을 충족하지 못했다. 실제 공장의 자동 합격·불합격 결정이나 생산 제어에 사용하지 않는다.

## 2. 데이터와 학습 범위

UCI SECOM 원본은 1,567행·익명 센서 590개다. 데이터 출처·다운로드 안내는 [README](../../README.md)를 따른다. 원본 label은 정상 `-1`, 불량 `1`이며 양성 label은 `1`이다.

이 후보의 학습 파일은 `data/splits/integrated/time_train.csv`이며 1,096행(정상 1,018·불량 78)을 사용했다. 저장 단계에서 Validation·Test를 학습하거나 평가하지 않았다. 모델 설정 선택에는 이전의 Train 내부 실험·시간 검증 결과가 사용됐다. 학습에 포함하지 않았다는 사실과 개발 과정에서 검증 결과를 관찰했다는 사실을 구분한다.

Train 생성 계약:

```text
time:7089b34af4376938c135ff1054d93b504004f74ec6ef59fb82f640a7e9c2b584
```

품질 필터는 학습 데이터에서 결측률 50% 초과 센서를 제거한 뒤 관측값 종류가 1개 이하인 센서를 제거한다. 기존 시간 검증 실행에서는 24개·122개를 각각 제거하여 444개를 유지했다. median 대치·센서 선택·분류기 학습은 해당 학습 구간 안에서 수행한다. OOF에서는 각 fold마다 센서를 선택하며 전체 Train의 고정 20개 목록을 과거 OOF에 소급 적용하지 않는다.

## 3. 선택과 분류기 설정

S0 선택기는 Random Forest 중요도 기반 Top-20이다. 트리 300개, 최대 깊이 제한 없음, `min_samples_leaf=1`, `class_weight=None`, seed 42를 사용한다. 중요도 순위가 아니라 선택기가 유지한 **원래 특징 순서**로 분류기에 전달한다.

M3 분류기는 XGBoost다. 트리 300개, 최대 깊이 2, `reg_lambda=5`, 학습률 0.05, `subsample=0.8`, `colsample_bytree=0.8`, `scale_pos_weight=1`, seed 42, `tree_method=hist`를 사용한다. 저장 실행의 병렬 수는 2다. adapter는 학습 때 label을 내부 0/1로 변환하고 추론에서는 원래 label을 반환한다.

배포 후보 객체에는 선택된 센서의 학습 median과 분류기를 보존한다. 이 XGBoost 경로에는 scaling이 없다. RF 선택기·수백 개 입력을 요구하는 품질 필터는 추론 때 실행하지 않는다. 센서 선택과 전처리 통계를 추론 입력으로 다시 학습하지 않는다.

## 4. 저장된 입력 계약

현재 manifest의 센서 순서:

```text
sensor_2, sensor_40, sensor_59, sensor_63, sensor_64,
sensor_65, sensor_67, sensor_71, sensor_153, sensor_166,
sensor_267, sensor_301, sensor_341, sensor_426, sensor_437,
sensor_441, sensor_475, sensor_477, sensor_539, sensor_562
```

입력은 위 센서만 포함한 UTF-8 CSV 또는 DataFrame이다. 컬럼 순서는 달라도 이름으로 맞춘다. label·timestamp·행 ID·추가 센서를 포함하지 않는다. 누락·중복 컬럼, 숫자가 아닌 타입, 무한대, 빈 입력, 모든 필수 센서가 NaN인 행은 거부한다. 존재하는 컬럼의 일부 NaN만 학습 median으로 대치한다.

출력은 모델 양성 확률, 후보 문턱 판정, 원래 label이다. CLI는 입력 행 번호도 기록한다. 모든 센서가 결측인 행을 거부하는 정책은 원본 전체 Pipeline의 median 대치 예측과 의도적으로 다르다. 단위·센서 의미 변경은 이름 검증만으로 감지하지 못하므로 다른 공장에 그대로 적용하지 않는다.

## 5. 후보 문턱과 성능 근거

저장된 후보 threshold는 **`0.036539457738399506`**이다. 예측 확률이 이 값 이상이면 양성으로 판정한다. 임시 프로젝트 정책은 Recall 80% 이상·양성 판정 비율 40% 이하다. 조건을 만족하는 Train 단일 OOF 후보 중 양성 비율 최소 → Recall 최대 → threshold 최대 순으로 선택했다. 현장 비용·검사 용량을 근거로 확정한 운영 문턱은 아니다.

양성 판정 비율은 `(TP + FP) / 전체 표본 수`로, 모델이 후속 확인 대상으로 선별한 비율이다. FP 비율만을 의미하지 않으며 실제 재검사 처리량이나 2차 검사의 성공률도 보장하지 않는다.

| 기존 평가 자료 | 표본 수 / 불량 수 | AP | ROC-AUC | Recall | Precision | 양성 비율 | TP / FP / FN | 80%·40% 정책 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| Train 단일 계층 5-fold OOF | 1,096 / 78 | 0.206358 | 0.786321 | 80.77% | 15.48% | 37.14% | 63 / 344 / 15 | 충족 |
| 시간순 Validation | 235 / 17 | 0.077252 | 0.523745 | 5.88% | 5.26% | 8.09% | 1 / 18 / 16 | 미충족 |
| 동결 저장 모델의 후속 시간 구간 | 236 / 9 | 0.040461 | 0.488008 | 11.11% | 3.23% | 13.14% | 1 / 30 / 8 | 미충족 |

OOF·Validation 근거는 [보고서 33절](report.md#33-시간-일반화-진단과-최근-기간-학습-대조-종합-2026-10-07), 후속 평가 근거는 [보고서 34절](report.md#34-동결-저장-모델의-후속-시간-구간-평가-2026-10-07)과 `logs/secom/v1/m3_frozen_time_evaluation/evaluation.json`이다. 단일 OOF는 시간순 OOF가 아니며 문턱 선택에도 사용했다. Validation도 반복 관찰한 개발 검증 자료다. 후속 평가는 `time_test.csv`를 사용했지만 과거 완전한 미사용 여부 보증이 없어 독립적인 미사용 Test 성능으로 표현하지 않는다.

OOF·Validation 행은 기존 같은 설정·Train 계약의 실험 결과이며 저장된 joblib을 다시 Validation에서 평가한 증거는 아니다. 후속 평가 행은 동결된 저장 객체를 복원하여 재학습 없이 평가한 결과다. 전체 M3 444센서 대비 Top-20의 기존 Validation AP 상대 하락은 14.60%지만 이번 후속 구간에는 전체 센서 비교가 없으므로 이 비율을 승계하지 않는다. 두 시간 구간의 절대 성능이 낮아 “20개로 충분한 현장 성능을 달성했다”고 주장하지 않는다.

## 6. 구현 정합성 확인

- 사용자 실행: 전체 Train 1,096행에서 전체 입력 경로와 20개 입력 경로의 확률 차이 0, 판정·label 일치. 선택 센서 전체 결측으로 제외한 원본 행은 0개다.
- 일부 NaN·컬럼 재정렬·단일 행·배치 독립성·전체 결측 거부 검사 통과. 절대 확률 오차 허용치는 `1e-12`다.
- 사용자 실행: 별도 Python 프로세스에서 복원한 검증 입력 33행의 확률 차이 0, 판정·label 일치.
- 사용자 실행: 데모 CSV 33행 예측 완료, 양성 판정 22행. Train 유래 검증 행과 NaN 시험 행이므로 이 비율을 신규 성능으로 사용하지 않는다.
- 저장·추론·동결 평가 관련 합성 테스트 17개 통과. 전체 프로젝트 테스트를 모두 최신 재실행한 것은 아니다. 이번 결과 문서화에서는 테스트를 다시 실행하지 않았다.

근거: `logs/secom/verification/m3_sensor_bundle_check/inference_check.json`, 후보 manifest의 학습 출처, 사용자가 공유한 별도 프로세스 복원·CLI 출력. 저장·복원·추론 정합성은 시간 일반화 성능 검증과 별개다.

## 7. 런타임과 파일 보안

저장 환경: Python 3.10.22, numpy 1.26.4, pandas 2.2.3, scikit-learn 1.5.2, XGBoost 2.1.3, LightGBM 4.5.0, joblib 1.6.0. 현재 복원기는 manifest와 런타임 버전이 다르면 거부한다. 사용자 정의 클래스는 `src` 모듈 경로로 복원하며 실행은 프로젝트 루트에서 `python -m src...`를 사용한다.

현재 adapter가 포함된 모듈은 LightGBM도 import한다. XGBoost 추론이라고 해서 LightGBM 설치 의존성이 자동 제거된 것은 아니다. Agent·외부 LLM API는 필요하지 않으며 추론은 현재 config를 읽지 않는다.

joblib은 역직렬화 시 임의 코드 실행 위험이 있다. 직접 생성한 신뢰한 파일만 복원한다. `--trusted-local-bundle`, 버전 확인, manifest 계약 확인은 보안 서명이나 안전한 역직렬화를 보장하지 않는다.

후보 묶음에는 로컬 검증용 센서 값 33행이 포함된다. 외부 공유·업로드하지 않는다. `/models/candidates/`와 CSV는 Git 추적 제외 대상이다. 이 카드는 원시 센서 값이나 학습 median 값을 공개하지 않는다.

## 8. 사용 제한과 다음 결정

시간 분포 변화와 결측 패턴 변화가 관찰됐지만 익명 센서만으로 공정 원인이나 성능 저하의 인과관계를 확정하지 못했다. 최근 30일 학습과 센서 고정 대조에서 평균 AP 개선이 확인되지 않아 전체 과거 경로를 연구·데모 기준으로 유지했다. 소표본·불균형, 미보정 확률, 반복된 개발 검증 관찰도 한계다.

후속 사용자 승인으로 저장 후보를 동결한 뒤 사용자가 236행을 평가했다. 실행 기록은 `completed`, `refit=false`이며 불량 9건 중 1건 검출·8건 미검으로 정책 미충족이다. 과거 완전한 미사용 여부는 보증하지 못하므로 “기존 데이터의 후속 시간 구간 평가”로 표현한다. 결과에 맞춰 모델·센서·threshold를 다시 조정하지 않는다. 평가 조건과 결과는 이 카드와 보고서 34절을 기준으로 하고, 당시 승인·준비 과정은 Git 이력에서 확인한다.

공통 CLI 사용법과 신규 입력 조건은 [실행 안내의 저장 묶음 검증·예측](USAGE.md#v2-저장-묶음-검증과-예측)을 참고한다. 해당 명령은 V2 예시이며 이 카드의 V1 모델 경로·문턱을 대체하지 않는다. 이 카드는 V1 manifest와 실험 기록의 수동 문서화다. 후보를 교체하거나 정책을 변경하면 함께 갱신해야 한다.
