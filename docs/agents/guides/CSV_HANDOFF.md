# CSV 전처리 결과 전달

완료된 통합 실행의 Train·Validation 결과를 새 로컬 묶음으로 복사한다. SECOM 전용 기능이 아니며, 현재 CSV 표형 계약을 사용하는 통합 실행을 대상으로 한다. 맵·이미지·Test 처리·모델 학습·게시 기능은 포함하지 않는다.

## 구현 파일

| 경로 | 기능 |
| --- | --- |
| `src/agents/csv_handoff_cli.py` | 완료 통합 실행 검증·허용 파일 복사·출처/안내 생성·새 전달 경로 확정 |
| `src/agents/csv_handoff_contract.py` | 로그 없이 묶음의 해시·상태·특징 순서·수치·행 연결 검사 |
| `tests/agents/test_csv_handoff.py` | 합성 연결·변조·상한·미완료/취소 실행 거부 검증 |

기존 후보/적용/통합 제어 소스는 변경하지 않아 완료된 실행의 코드 식별값을 유지한다. 원래 실행은 파일을 제공할 뿐이며 worker를 다시 실행하거나 fit·transform을 호출하지 않는다.

## 출력

```text
data/processed/agents/handoffs/<name>/
├─ prepared/
│  ├─ train_features.csv
│  ├─ validation_features.csv
│  ├─ train_rows.json
│  ├─ validation_rows.json
│  ├─ application.json
│  └─ application.md
├─ preprocessor.json
├─ feature_mapping.json
├─ provenance.json
├─ README.md
└─ HANDOFF_COMPLETE.json
```

- 특징 CSV와 rows.json은 새로 계산하지 않고 정확한 바이트를 복사한다.
- 저장 기준은 후보에서 복사한다. Train에서 산출한 기준과 출력 특징 순서를 그대로 유지한다.
- feature_mapping은 저장 상태의 기록 순서로 원본 컬럼·출력 위치를 연결한다. 이름을 분해해서 센서를 추측하지 않는다. 인덱스는 중요도 순위가 아니다.
- provenance에는 통합 계획·후보·적용 실행의 식별값과 적용 binding을 보존한다. 원본 폴더·승인 DB는 복사하지 않는다.
- README는 수신자가 특징 행과 라벨/ID 문자열을 연결하는 방법을 설명한다. 프로젝트별 라벨 숫자 변환을 강제로 적용하지 않는다.
- 완료 기록의 payload_bytes는 목록에 있는 파일 크기의 합계다. 사용자 max_bundle_bytes 상한은 완료 기록 자체의 크기까지 포함한다.

## 생성 및 검사

사용자가 이미 완료한 `secom-module-prep01`을 전달하는 예시다. 전처리 실행은 반복하지 않는다.

```powershell
python -m src.agents.csv_handoff_cli export `
  --pipeline-name secom-module-prep01 `
  --name secom-prepared01 `
  --max-bundle-bytes 134217728 `
  --confirm-local-export

python -m src.agents.csv_handoff_cli verify --name secom-prepared01
```

정상 생성은 `handoff_created`, 정상 검사는 `handoff_verified`다. 검사는 새 승인·worker·모델을 생성하지 않는다. 묶음을 전달받은 사용자는 같은 프로젝트 환경의 `data/processed/agents/handoffs/<name>`에 놓고 verify로 검사할 수 있다. 원래 logs는 필요하지 않는다.

## 검증·보안 경계

생성 전후 원래 실행의 커밋·승인·파일·운송 증거를 기존 실행기로 검증한다. 후보 검토만 완료한 실행, 미완료 적용, 취소 요청, 변경된 코드/계획/후보는 거부한다. 통합 실행 잠금을 사용해 다른 통합 명령과 동시에 진행하지 않는다.

복사는 일반 파일만 허용하고 링크·재분석 지점·하드 링크를 거부한다. 파일 목록은 고정한다. 스트리밍 복사 중 합계 상한을 강제하고, 생성 JSON은 쓰기 전 조각별 상한을 검사한다. 메타데이터는 최대 8 MiB, 완료 기록은 64 KiB 이하이며 전체 요청 상한은 최대 2 GiB다. 일부 행을 자르거나 상한을 자동으로 늘리지 않는다.

새 `.partial-<ID>` 폴더에 준비해 파일 검사 후 같은 부모의 최종 이름으로 이동한다. 실패한 부분 폴더는 자동 삭제하지 않으며 완료 묶음으로 안내하지 않는다. 기존 전달 이름은 덮어쓰지 않는다. 부분 결과에는 실제 데이터가 포함될 수 있으므로 로컬에서만 관리한다.

독립 verify는 파일 해시·JSON 상태·원본 특징 매핑·숫자 유한성·허용 결측·행 수·컬럼 순서·행 위치 해시·구간 비중복을 검사한다. 원본 데이터는 읽지 않으며 모든 수치·라벨의 진실성이나 원래 승인 DB 전체를 독립 인증하지 않는다. 파일과 manifest를 함께 바꿀 수 있는 로컬 관리자에 대한 진본 인증도 아니다.

내보내기는 사용자가 명시적으로 선택한 로컬 복사다. 외부 공유 승인이나 에이전트 자동 게시가 아니며 네트워크 전송·권한 확대·Git 추적 추가는 하지 않는다. 기존 `/data/**` 제외 규칙을 그대로 적용한다. 묶음에는 실제 특징·라벨·ID·처리 통계가 있으므로 LLM·외부 추적 서비스로 보내지 않는다.

## 테스트

```powershell
python -m unittest tests.agents.test_csv_handoff -v
```

테스트는 합성 입력·기존 실제 전처리 코어·승인/커밋 연결을 사용하고 네이티브 운송만 모의한다. 실제 데이터의 내보내기는 사용자 실행으로 별도 확인한다.

전달 테스트 5개가 통과했다. 각 테스트의 하위 사례로 특징 순서·비유한 수치·행 위치·원본 특징 매핑·출처 변경, 파일 추가/누락, 상한 초과와 미완료/취소 실행 거부를 확인했다. 실제 SECOM 전달 묶음은 아직 생성하지 않았다.

## 후순위 검토: 형식 중립 전달 코어와 어댑터

기록일: 2026-10-17. 사용자 결정으로 구현을 보류하고 추후 검토 항목으로만 보존한다. 아래는 현재 실행 가능한 기능이나 확정된 상세 계약이 아니다. 이 기록으로 코드·설정·기존 실행 결과를 변경하지 않는다.

현재 `csv_handoff_cli.py`에는 완료 실행 확인·복사·용량 제한·최종 경로 확정이, `csv_handoff_contract.py`에는 CSV 전용 구조·행 연결 검증이 구현되어 있다. WM의 Train·Validation 캐시와 Dataset 검사 결과를 전달하는 새 묶음 기능은 아직 구현하지 않았다.

검토 방향은 **공통 전달 코어 + 등록된 형식별 어댑터**다. 범용화는 임의 파일을 자동 해석하는 것이 아니라, 등록·검토된 어댑터를 동일한 전달 절차로 연결한다는 뜻이다.

| 구분 | 추후 검토할 범위 |
| --- | --- |
| 공통 코어 | 허용 파일 목록, 경로·링크 검사, 스트리밍 복사, 합계 용량 제한, 복사 전후 해시, 덮어쓰기 방지, 부분 폴더 검증 후 최종 경로 확정 |
| 어댑터 등록부 | ID·버전별 완료 증거 확인기, 포함 파일 목록, 결과 검증기 연결. 임의 코드 자동 등록·실행은 허용하지 않음 |
| CSV 어댑터 | 기존 전처리 설정·특징 순서·수치 형식·행 연결 검증 재사용 |
| WM 어댑터 | 완료된 Dataset 검사 증거 확인, Train·Validation 캐시·색인·클래스 매핑·변환 설정·검사 보고서 연결 |
| 공통 CLI | 어댑터 선택, 로컬 전달 생성·검증, 사용자 확인 또는 승인 방식 명시 |
| 테스트·문서 | 다른 경로로 옮긴 뒤 원래 logs 없이 검증, 변조·누락·추가 파일·구간 중복·용량 초과·기존 이름 덮어쓰기 거부 |

재개 시 다음 사항을 먼저 결정한다.

- [ ] 공통 코어를 둘 위치와 어댑터 입력·출력 계약을 확정한다.
- [ ] 로컬 복사 확인과 실행 승인 저장소를 어떤 방식으로 연결할지 결정한다. 현재 CSV의 명시적 확인 옵션과 worker의 단계별 승인을 동일한 것으로 간주하지 않는다.
- [ ] 형식별 예상 크기와 사용자 요청 상한·보안 상한을 구분한다. 기존 CSV의 2 GiB 상한을 WM 때문에 일괄 확대하지 않는다.
- [ ] WM 묶음은 Test·원본 pickle·모델·승인 DB·Python/PyTorch 설치 파일을 제외한다. 수신 환경의 의존성은 사용 안내로 명시한다.
- [ ] 소비자 검증은 원래 실행 폴더 없이 가능하게 하되, 해시 검증을 진본 인증이나 성능 보증으로 표현하지 않는다.
- [ ] 기존 승인·완료 실행의 소스 해시 연결 영향을 확인한 후 이전한다. 우선 새 파일로 확장하고 기존 CSV 경로 이전은 별도 회귀 검증 후 진행한다.

AppContainer·Job·승인 DB·EDA·분할·전처리·캐시 생성·`WaferDataset`을 다시 구현하거나 데이터를 재변환·모델을 재학습하는 작업은 이 검토 범위에 포함하지 않는다. 데이터의 LLM 전송 금지, 자동 공유·Git 업로드 금지, 원본 보존 원칙도 유지한다.
