# LLM 정보 전달 정책·결과 해설 설계

기록일: 2026-10-16. 갱신일: 2026-10-18. 상태: **사용자 합의한 전달 정책·전송 확인 흐름 설계 반영, 선택형 공개 제어·결과 해설·설정 UI 미구현**.

이 문서는 LLM 정보 전달 정책의 합의 사항과 후속 구현 범위를 정리한다. 설계 합의는 실제 자료의 전송 승인이 아니며, 현재 코드의 데이터 전달 금지를 해제하지 않는다. 아래 항목은 설정 UI·전송 제어 계층을 구현·검증한 뒤 사용할 목표 동작이며 현재 CLI 옵션이 아니다.

## 0. 확정한 사용 흐름 — 2026-10-18

사용자는 **설정 화면에서 기본 허용 범위를 정하고, 해설받을 자료를 선택한 뒤 실제 전송 내용을 확인하여 전송**하는 방식에 동의했다. 설정 저장만으로 전송하지 않는다.

```text
설정: 사용 목적·대상 모델별 허용 항목 저장
                     ↓ 실제 전송 없음
결과: 해설받을 표·집계·그림 선택
                     ↓ 허용 범위·지원 기능 검사
전송 미리보기: 실제 전달 내용·수신 대상·추측 위험 확인
                     ↓ 사용자가 [전송하고 해설받기] 선택
전송 직전: 정책·모델·자료·내용의 일치와 승인 유효성 재검증
                     ↓ 일치한 요청에 한해 1회 전송
결과: LLM 해설 표시 — 실행 승인·품질 판정으로 사용하지 않음
```

정책에서 허용하지 않은 항목은 선택·전송을 차단한다. 일부 항목을 제외할 수는 있지만, 제외 사실과 최종 전송 내용을 반드시 미리보기에 표시한다. 확인 뒤 몰래 추가·제외·치환하지 않는다. 로컬 UI에서 표·그림을 열어보는 것은 LLM 전송과 별개이며, 설정 허용이나 열람을 전송 동의로 간주하지 않는다.

LLM 정보 전달 승인·전처리 실행 승인·LangSmith 추적 허용·대화 저장 설정은 서로 별개다. 대상 모델이 로컬인지 외부 API인지도 UI 서버가 로컬인지와 구분한다.

## 1. 사용자 제안과 목표

사용자가 선택한 모듈로 EDA·검사·변환 파이프라인을 만들고, 필요하면 LLM이 표·그림 아래에 간략한 해설을 붙인다. 2026-10-18 사용자 결정 방향은 일괄 보안 등급보다 기능별로 전달 항목을 선택하고 실제 전송 내용을 확인·허용하는 방식이다. 사용자는 허용한 정보에서 생길 추측 위험을 인지하고 선택하며, 시스템은 승인 범위를 넘겨 보내지 않도록 강제한다. 이는 현재 실제 데이터 전송을 허용하거나 해당 기능이 구현됐다는 뜻은 아니다.

LLM의 기본 역할은 자연어 요청 해석·등록 모듈 설명·실행안 제안·설정 안내·진행 상태 설명이다. 실제 데이터 기반 해설은 별도 정보 전달 계약과 승인 기능을 구현·검증한 경우에만 선택적으로 추가한다. 전처리 계산은 등록된 코어/worker가 수행하며 LLM 없이도 같은 파이프라인이 동작해야 한다.

## 2. 검토 시작의 선행 조건

- [x] 등록된 내장 모듈 범위의 공통 계약과 표형·WM 통합 등록부 정비.
- [x] 지원하는 표형·WM 파이프라인 설정과 입력/출력·순서·의존성 검증 구현.
- [x] 내장 EDA·품질 코어의 모듈 재사용과 기존 승인·격리 실행·결과 검증 연결.
- [ ] 모듈별 보고서 출력 계약에 그래프/표의 의미·단위·판정 근거·해석 한계 정의.
- [ ] 규칙 기반 실행과 로컬 해설만으로 정상·실패·검토·취소 경로 검증.

현재 통합 등록부, 지원 모듈의 설정·조합 검증, 표형 모듈 실행과 WM 정상 6단계의 공통 생성·배정·승인·실행을 구현했다. 사용자 모듈은 검토된 참조 모듈의 합성 실행 범위이며 임의 코드·모든 형식의 자유 조합을 지원하지 않는다. 로컬 Qwen·LangChain·LangGraph의 질문·답변에서 제안 저장·복원·입력 결합·별도 승인·합성 정상/품질 검토 중단 경로까지 확인했다. 선택형 공개 제어 계층·실제 결과 해설은 아직 구현하지 않았다. 개별 worker마다 LLM 호출을 중복 추가하지 않는다. 최신 범위는 [구현 안내](../GUIDE.md)를 따른다.

## 3. 해설의 두 종류

| 구분 | 정보와 생성 방식 | 표현 원칙 |
| --- | --- | --- |
| 읽는 방법·일반 설명 | 검토된 모듈 설명·그래프 종류·지표 의미만으로 LLM 또는 고정 템플릿 작성 | 실제 데이터를 확인한 결론처럼 표현하지 않음 |
| 이번 결과의 관찰 | 로컬 규칙으로 생성하거나 별도 승인한 집계 DTO를 LLM에 전달 | 관측·가설·해석 한계를 구분하고 원인/인과를 단정하지 않음 |

예시: 결측률 그래프의 축·막대 의미는 데이터 없이 설명할 수 있다. 실제 기준 초과 여부·컬럼·건수는 로컬 결과로 작성한다. 상세 수치를 로컬에서만 삽입하는 방식에서는 완성된 문장을 LLM에 다시 보내지 않는다.

모듈별 출력의 목표 구성은 `표·그림 / 읽는 방법 / 이번 결과 해설 / 주의사항`이다. LLM 해설이 없어도 보고서가 정상 생성돼야 한다.

## 4. 설정 화면의 범위

### 4.1 목적·수신 대상·항목의 분리

| 설정 축 | 선택 범위 | 적용 원칙 |
| --- | --- | --- |
| 사용 목적 | 실행안 제안·질문 / 결과 해설 / 정제된 오류 설명 | 목적별 허용 범위를 분리 |
| 수신 대상 | 로컬/외부, provider·endpoint·모델 구성 | 로컬의 허용 범위를 외부 API로 자동 이전하지 않음 |
| 전달 항목 | 아래 기능별 항목 | 미지원 항목은 활성화하지 않음 |

초기 엄격·제한 해설·로컬 분석이라는 단일 모드 이름 대신 이 세 축으로 설정한다. 로컬이라는 이유만으로 데이터 접근·전송을 허용하지 않는다. 첫 연결은 로컬 Ollama이며 외부 API·LangSmith를 선택 가능한 구현 기능처럼 표시하지 않는다.

### 4.2 전달 항목과 기본값

| 항목 | 내용 | 첫 기본값·경계 |
| --- | --- | --- |
| 요청·대화 | 사용자가 작성한 요청·검증된 질문·답변 | 전송 전 확인. 임의 문장에 사용자가 직접 넣은 정보도 전달됨 |
| 공개 기능 명세 | 등록 모듈·버전·지원 설정 설명 | 제안 목적에 허용하되 전송 미리보기에 포함 |
| 작업 상태 | 완료·검토·실패 단계·정제된 코드 | 차단 |
| 데이터 구조 | 컬럼 수·자료형·역할 | 차단 |
| 실제 컬럼명·라벨명 | 센서명·분류명 등 | 차단, 구조 항목과 별도 선택 |
| 집계 | 결측률·분포·상관계수·표본 수 등 | 차단, 지원하는 고정 양식부터 연결 |
| 결과 표 | 선택한 표의 승인된 행·열 | 차단, 임의 CSV 업로드와 구분 |
| 결과 그래프 | 선택한 그림 | 차단, 모델 기능·이미지/문자 메타데이터 검토 후 후속 연결 |

첫 버전의 선택 범위에서도 원본 파일·원본 행·샘플·배열·웨이퍼 이미지·실제 경로·원문 예외·전체 실행 로그는 제외한다. 비밀 키·인증정보·승인 토큰·승인 DB는 분석 정보 공개 설정으로 허용하지 않는다. 원본 전달 지원은 기존 원칙을 변경하는 별도 설계가 필요하다. 그래프를 허용했다고 원본 웨이퍼 이미지를 전달할 수 있는 것은 아니다.

표의 컬럼 헤더·셀, 그래프의 제목·축·범례·부가정보에도 식별명·수치·경로가 들어갈 수 있다. 상위 항목 허용이 다른 항목의 차단을 무효화하지 않도록 교차 검사한다. 예를 들어 표 허용·실제 컬럼명 차단이면 이름을 그대로 전송할 수 없고, 검토된 대체 표현을 미리 보여 주거나 전송을 차단한다. 임의 자유 텍스트·원본 행이 섞인 표는 등록된 결과 표로 추정하지 않는다.

집계도 센서명·공장명·라벨 비율·정확한 건수·시간별 변화 등으로 정보를 추측하게 할 수 있다. 식별자 제거·익명화·반올림·높음/낮음 변환이 추측 불가능함을 보증하지 않는다. UI는 남는 위험을 표시하고 사용자는 실제 내용을 확인한다. 사용자 선택이 시스템의 범위 강제 책임을 없애지는 않는다. 자유 문장의 민감정보를 모두 자동 탐지할 수 있다고 주장하지 않는다.

### 4.3 설정·결과 화면의 책임

- 설정 화면: 대상·목적별 허용 항목을 편집하고 `[기본 정책 저장]`으로 저장한다. 동작은 로컬 정책 저장뿐이며 기존 자료·대화를 자동 전송하지 않는다.
- 결과 화면: 지원하고 허용된 해설 자료를 선택한다. 미지원·금지 항목은 이유와 함께 선택을 차단한다. 승인 DB나 자유 파일 경로를 선택 대상으로 제공하지 않는다.
- 전송 확인 화면: 대상 모델·목적·정책 버전·선택 자료·제외/변환 내역·실제 요청 내용을 표시하고 `[전송하고 해설받기]` 확인을 받는다. 원본 파일을 열어 보는 것과 다르다.
- 내용이 바뀌면 이전 미리보기·전송 확인을 무효화한다. 모델 구성·수신 대상·정책 버전·선택 자료·행/열 범위·본문 변경은 새 미리보기와 새 확인이 필요하다. UI 상태만 믿지 않고 전송 직전 서비스 계층에서 검사한다.

첫 화면에 체크박스를 표시하는 것만으로 기능 구현 완료라고 간주하지 않는다. 양식·정책·전송 확인·제공업체 경계·응답/로그 처리가 연결되고 검증된 항목만 활성화한다.

## 5. 전송 승인·격리 경계

1. 결과를 읽는 신뢰된 로컬 축소기가 등록된 해설 양식의 필드만 추출한다. 임의 표 전체·그림·보고서 원문을 자동 첨부하지 않는다.
2. 보내려는 정확한 payload와 수신 대상(로컬/외부·provider·endpoint·모델)을 로컬에서 미리 보여 준다.
3. 사용자 승인은 실행·결과 묶음·양식 버전·payload 내용 식별값·수신 대상·유효기간·사용 횟수에 결합한다. UI 확인 문구만으로 기존 처리 승인을 전송 승인으로 간주하지 않는다.
4. 정책 버전·모델 구성·필드·선택 자료·내용·수신 대상 변경은 재확인을 요구한다. 확인 후 payload를 더 상세하게 바꾸지 않는다. 승인 만료·이중 클릭·재사용·동시 요청도 서버 측에서 검사하고 전송 승인은 1회 소비한다.
5. 전처리 worker는 외부 통신을 계속 금지한다. 선택적으로 허용하는 LLM 연결은 별도 권한·egress 경계에서 축소 payload만 받는다.
6. 로컬 endpoint 검증 실패·응답 장애 시 외부 API로 자동 전환하지 않는다. 전송 시도 후 응답을 못 받았어도 미전송이라고 단정하지 않으며 자동 재시도하지 않는다. 재전송하려면 새 확인이 필요하다. LLM 미사용 또는 출처가 구분된 고정 로컬 해설로 중단/복귀한다.
7. 전송·해설 승인은 삭제·변환·모듈 등록 승인을 대신하지 않는다. Train-only·누수 방지·임의 코드 실행 금지·Job 제한도 완화하지 않는다.

해시·승인 기록은 내용 일치 확인을 위한 것이며 익명성이나 안전성을 인증하지 않는다. 기존 승인 API의 재사용 가능 범위와 해설 전용 승인 계약의 필요성을 설계 때 검토한다.

## 6. LLM 응답과 이력 관리

- LLM 출력은 해설 텍스트만 허용한다. 셸 명령·함수 실행·동적 모듈 등록·정책 변경으로 해석하지 않는다.
- 출력 길이·필드·형식을 제한하고 요청에 없는 수치·센서명·원인 단정 등 근거 없는 주장을 검토한다. 완벽한 사실성 보증은 주장하지 않는다.
- 로컬 결과의 문자열은 지시문이 아닌 데이터로 취급한다. 가능하면 첫 버전은 자유 텍스트 필드를 제외한다.
- 사용 모델·모드·양식 버전·승인 참조·성공/실패와 로컬 생성 설명인지 LLM 설명인지 구분한다.
- 감사 로그·오류·SDK tracing·LangSmith·자동 업로드·telemetry에 프롬프트/집계/응답이 복사되지 않는지 검증한다. 해시만 남기는 경우에도 보존·접근 정책을 정한다.
- 전송 후 승인을 취소해도 이미 외부로 보낸 정보를 회수할 수 있다는 보장은 하지 않는다. provider의 보존·학습 사용·삭제 조건은 선택 시 별도로 확인한다.

## 7. 추가 구현 범위와 단계

| 기능 묶음 | 추가 작업 |
| --- | --- |
| 항목별 정책 | 기본 거부, 목적·대상별 허용 양식·필드·수신 대상·정책 버전 |
| 해설 입력 생성 | 로컬 결과 축소·검증·버전 관리, 데이터 유래 자유 텍스트 제한 |
| 사용자 승인 | payload 미리보기·전송 전용 승인·변경/만료/재사용 거부 |
| LLM provider | 로컬/외부 연결·키 분리·timeout·비용/재시도 한도·안전한 fallback |
| 결과 표시 | 제한된 응답 검증·로컬 보고서 삽입·생성 방식/한계 표시 |
| 보안 검증 | 금지 필드 혼입·prompt injection·수신 대상 변경·로그 유출·응답 실패·승인 경쟁 |

설정 저장과 개별 전송 확인의 분리는 확정했다. 항목별 양식·제공업체 지원·구현 우선순위의 권장 순서는 다음과 같다.

1. 모듈형 rules-only 파이프라인과 로컬 결정적 해설 완성.
2. 데이터 없는 모듈/그래프 설명과 기본 차단 정책·전송 미리보기 연결.
3. 고정 집계 양식 **하나**의 미리보기·사용자 승인·해설 추가.
4. 로컬/외부 수신 대상의 별도 검증과 선택 범위 확대.
5. 임의 표·그림·자유 필드 전송은 초기 범위에서 제외하고 필요 시 새 보안 검토.

추가 규모는 설정 몇 개가 아니라 별도의 정보 전달·승인·검증 기능 묶음이다. UI/CLI 수준·provider·허용 양식이 정해지기 전에는 기간을 단정하지 않는다. 기존 snapshot·worker·승인 기반을 재사용하되 모두 다시 구현하지 않는다.
