# LLM 정보 전달 정책·결과 해설 설계

기록일: 2026-10-16. 갱신일: 2026-10-20. 상태: **로컬 결과 해설·기본 전달 정책·민감도별 확인 UI 구현. 외부 API 전송은 미지원**.

## 현재 구현 — 2026-10-20

### 정상 사례와 정책 통합 검사 마무리 — 2026-10-20

최종 공통 UI 회귀 검사: **177개 통과**. 자동 훅의 단발 호출과 최초 응답 보존까지 포함한 결과이며, 실제 모델·AppContainer 실행·전처리 재실행을 수행한 검사는 아니다.

사용자 수동 실행에서 `pairs-v2`, 센서쌍 66개, 문맥 16,384, 요청 시각 `2026-10-19T22:34:57.181430+00:00`의 해설 완료를 확인했다. 저장된 CSV 집계와 대조한 주요 센서쌍·평균·결측률은 일치했다. sensor_3–6 계수 약 −0.638, sensor_2–7 약 −0.391, sensor_5의 결측 제외 관측값이 100으로 일정하다는 설명이 해당한다. 다만 “약한 상관”, “비교적 좁은 분포” 같은 표현은 기준이 없어 주의가 필요하다. 이는 한 번의 정상 전달·생성 사례이지 모든 자연어 해설의 사실 정확성 인증이 아니다.

정책 통합 검사는 실제 임시 SQLite 단발 기록과 자동 완료 훅을 연결하고 모델 운송만 합성 응답으로 대체한다. 기본 허용된 일반 자료의 한 번 호출, 중복 완료 통지의 원래 해설·시각 보존, 미분류·민감 제외·민감 개별 확인·기본 허용 해제·모델 변경 시 자동 호출 차단을 확인한다. 차단 시 결과 파일을 읽는 단계에도 진입하지 않는다. 중복 호출은 막히지만 기존 해설을 “이미 요청함”으로 덮는 표시 문제를 발견해 원래 응답을 보존하도록 수정했다. 기존 사용자 작업·실제 모델은 추가 실행하지 않았다.

이 절은 아래 2026-10-18 설계의 일괄 건별 확인 방식을 변경한다. 과거의 “결과 해설 미구현·전송 전부 금지” 설명은 이 절의 제한된 구현에 한해 대체한다.

- 로컬 LLM: 사용자가 설정에서 기본 허용을 저장하고 작업 시작 전에 일반 자료로 분류하면, 명시적 실행 명령의 완료 직후 검증된 결과를 한 번 해설한다. 기본값은 비허용이며 기존 완료 작업·결과 열람·화면 갱신으로 자동 호출하지 않는다.
- 외부 API: 로컬 기본 허용을 상속하지 않고 항상 실제 전달 자료별 확인을 요구한다. 정책 판정만 구현했으며 공급자·API 키·전송 연결은 없다. 이번 구현은 외부 API를 사용할 수 있다는 뜻이 아니다.
- 민감 자료: 사용자 분류에 따라 항상 제외하거나 자료별 확인한다. 미분류는 자동 전달하지 않는다. 민감도를 자동 탐지·보증하는 기능은 아니다.

설정의 `해설 전달 정책 저장`은 `logs/agents/commentary/policy.json`에 저장한다. 현재 모델·주소·포트·생성 옵션 전체에 기본 허용을 결합하므로 모델 설정 변경 후에는 다시 저장해야 한다. 모델·자원 설정 자체는 기존처럼 브라우저 세션에만 보존한다. 해설 정책 저장은 전처리 실행 승인이나 모델 호출이 아니다.

완료 후 자동 해설은 허용 목록의 집계 CSV·보고서 내 Markdown 표와 선택적으로 허용한 집계 PNG만 사용한다. 원본 행 CSV·전체 보고서 본문·승인 DB·로그·전처리 객체·원본 웨이퍼 맵·예시 PNG는 대상으로 삼지 않는다. 실제 특징명·클래스명·집계 수치·그림 축은 포함될 수 있으므로 추측 위험은 사용자 분류 시 고려한다. 허용 자료가 없거나 텍스트 24 KiB·자료 16개·PNG 4개/각 2 MiB 상한을 초과하면 일부만 잘라 보내지 않고 해설을 중단한다.

5 결과 확인의 `로컬 결과 해설`에서는 미리보기에서 실제 표·그림·수신 모델·제외 파일을 확인하고 한 건을 요청할 수 있다. 민감 자료 확인은 자료·정책·모델·민감도 해시에 결합된다. 그래프는 설치 모델의 이미지 입력 지원이 필요하며, 지원 실패 시 텍스트로 몰래 전환하거나 다른 모델로 재시도하지 않는다. 해설은 일반 텍스트로 표시해 모델이 만든 링크·HTML·이미지 문법을 실행하지 않는다.

모델 호출은 UI 부모 프로세스에서 loopback Ollama로만 전달한다. worker의 AppContainer·네트워크 정책은 변경하지 않는다. 프록시·리다이렉트·LangSmith·외부 fallback·자동 재시도는 없다. SQLite 단발 명령 기록에는 요청 식별 해시와 상태만 남기며 해설 응답은 브라우저 세션 메모리에만 보관한다. 새로고침·동시 클릭·재시작에서 같은 자동 요청을 다시 전달하지 않는다. 응답을 잃은 경우에도 자동 재전송하지 않는다. 전송 시작 후 정책을 변경해 이미 보낸 내용을 회수할 수는 없다.

해설 오류는 완료된 전처리 결과·품질 상태·실행 승인을 바꾸지 않는다. LLM 해설은 수학적 결과 검증이나 품질 판정에 사용하지 않는다. 현재 일반화된 표의 행·열 선택 편집기, 외부 API 커넥터, 해설 영구 저장, 자동 민감 정보 탐지는 미구현이다.

구현: `src/ui/commentary_policy.py`, `commentary_service.py`, `commentary_transport.py`, `commentary_view.py`. 공통 승인 완료 지점과 CSV·WM 결과 화면에 연결한다. 실제 모델·실데이터 전송 테스트는 사용자가 설정과 자료를 확인한 뒤 별도로 수행한다.

검증: 공통 UI 회귀 검사 **163개 통과**. 합성 자료로 기본 차단·모델 변경·민감 자료 확인·동시 호출의 단발 기록·정책 철회·그래프 운송의 크기/응답 제한·Streamlit 미리보기의 모델 미호출을 확인했습니다. 실제 Qwen 답변 품질이나 외부 API·실데이터 전송을 검증한 결과는 아닙니다.

### 그래프의 집계 근거 연결 — 2026-10-20

센서 쌍 대응 보완: 모델에 전달하는 상관 문맥을 행렬 두 개에서 `feature_a`, `feature_b`, `pearson`, `observed_count`가 결합된 레코드 목록으로 변경했다. 표시 특징 내 모든 비중복 쌍을 포함하고 자기상관·대칭 중복은 제외하며, 절댓값 내림차순으로 정렬하고 계산 불가 `null`은 뒤에 둔다. 원래 그림·전체 CSV·계산 결과는 변경하지 않는다. 분포 문맥에는 통계가 결측 제외 관측값 기준이고 `count`는 전체 행 수가 아니라는 안내를 추가했다. 강함·약함 기준이 없는 임의 등급 부여와 서로 다른 쌍의 이름·수치 혼합을 금지하도록 지시한다. 관련 검사 50개 통과. 기존 결과의 12개 표시 특징에서 66개 쌍, 본문 11,393바이트를 확인했고 실제 모델은 호출하지 않았다. 입력 레코드의 대응을 검사한 것이며 자연어 응답의 사실 정확성 보증은 아니다. 전달 항목이 바뀌므로 기존 결과를 다시 조회하고 새 미리보기를 확인한 후 별도 요청해야 한다.

합성 문맥 초과 재현: 로컬 Qwen에 합성 단색 PNG 1장·3장과 짧은 문장을 보낸 경우 HTTP 200이었다. 기존 그래프와 같은 크기(1200×600, 960×840, 1440×1440)의 합성 그림 3장과 합성 수치 문자열 4,832바이트를 함께 전달하자 문맥 8,192에서 `request (8302 tokens) exceeds the available context size (8192 tokens)`라는 HTTP 400을 재현했다. 같은 입력을 문맥 16,384로 요청하면 HTTP 200, `prompt_eval_count=8302`였다. 합성 검사의 출력 한도를 32토큰으로 제한했으므로 마지막 응답은 `done_reason=length`이며 완성된 해설 품질 검증이 아니다. 사용자 그림·집계·기존 요청은 전송하지 않았다. 서버 표현 `context size`를 고정 분류에 추가했다. 실제 사용자 실패의 원문은 소급 복원할 수 없지만 같은 요청 구조의 문맥 초과를 재현한 근거이며, 사용자 설정은 자동 변경하지 않는다. 설정 변경 시 모델 설정 적용과 해설 정책 재저장 후 새 요청이 필요하다.

검증: 공통 UI 169개와 그래프·CSV 서비스 관련 검사 49개가 각각 통과했다(두 실행의 검사 범위는 일부 중복). 기존 `csv-ui-split01` 결과를 읽기 전용으로 조회해 세 그림의 근거 연결, 결측률 표시 범위가 전체가 아닌 점, 최고 결측률이 90% 초과인 점, sensor_2–4의 음의 상관을 확인했다. 실제 모델은 호출하지 않았다. 기존 화면 캐시에는 새 근거가 없을 수 있으므로 `결과 정합성 검사·열기`를 다시 눌러 조회한 뒤 전달 미리보기를 확인해야 한다. 이는 전처리 재실행이 아니다.

CSV 분할 작업의 기존 EDA 결과에서 커밋·도메인 검증을 통과한 `missing.csv`, `numeric_statistics.csv`, `pearson.csv`, `correlation_support.csv`와 승인 프로파일의 그래프 특징 상한을 읽는다. 표시 파일과 별도로 로컬 근거 복사본을 만들고, 기존 파일 해시·크기·전후 상태 검사를 동일하게 적용한다. 이 연결은 원본 CSV를 읽거나 EDA·worker를 재실행하지 않는다.

집계 표와 그래프 전달을 모두 허용한 경우 같은 보고서 폴더의 근거만 연결한다. 결측률은 내림차순 상위 특징의 비율과 전체 특징 수, 분포는 입력 순서상 표시 특징의 기술통계, 상관도는 표시 부분 행렬·변수 쌍 관측 수를 전달한다. `null`은 계산 불가로 보존하며 0으로 바꾸지 않는다. 그림에 대응하는 선택 범위를 명시적으로 추출한 것이며 전체 집계 CSV를 모델에 보내지 않는다. 결측률 동점 순서와 행렬 슬라이싱은 기존 표형 그래프 생성기와 같은 방식을 따른다.

수치 전달은 `집계 표 전달` 허용에 종속한다. 그래프만 허용했으면 집계는 추가하지 않고 수치 미허용 안내만 보낸다. 실제 전달할 수치와 범위는 그림 아래 미리보기에 표시하고 요청 해시에 포함한다. 대응 근거가 없는 WM 등 다른 그래프 경로에는 표형 선택 규칙을 임의로 적용하지 않고 근거 미제공으로 표시한다. 수치 근거 우선·부분 그림의 전체 일반화 금지 지침을 추가했지만 실제 모델의 수학적·시각적 정확성을 보증하지는 않는다. 과거 결과·승인·모델 호출 기록을 변경하거나 해설을 자동 재전송하지 않는다.

### 해설 표현·새 요청 — 2026-10-20 보완

실행 코드·입력 구분 보완: 결과 화면은 `해설 화면 코드 버전: pairs-v2`를 표시하고, 실제 전송이 시작된 요청에는 요청 버전·입력 형식(센서쌍 목록/행렬/수치 근거 없는 그림/표)과 상관 센서쌍 수를 세션 진단에 추가한다. 표시 시점에 새 값을 만들어 과거 해설에 붙이지 않는다. 완료 응답에 시각·입력 형식 기록이 없으면 현재 코드로 새로 생성된 응답인지 확인할 수 없다고 안내한다. 요청 원문·실제 센서명·집계 값은 이 버전 메타데이터나 SQLite 명령 기록에 추가하지 않는다. 최근 호출 완료 기록이 있다는 사실만으로 새 입력 구조가 전달됐거나 응답이 정확하다고 판단하지 않는다. 관련 합성 검사 51개 통과. 실제 모델·기존 작업은 재실행하지 않았다.

적용 설정·시도 구분 보완: 해설 시도 시각(UTC)과 실제 요청에 넣은 `num_ctx`를 응답 상태와 함께 세션에 표시한다. 서버가 `request (N tokens) exceeds the available context size (M tokens)` 형태로 응답하면 9자리 이내 숫자만 추출해 입력 토큰 수·허용 한도를 표시한다. 요청 시도와 무관한 다른 숫자나 원문은 보존하지 않는다. 설정 화면의 적용 문맥 길이와 해설 화면의 다음 요청 문맥 길이도 표시한다. 이전 실패가 남아 있는 것을 새 요청 실패로 오해하지 않도록 시각을 구분하며, 과거 기록에 없는 값을 소급 추측하지 않는다. 문맥 16,384 적용 → 해설 정책 저장 → 화면 재표시에서도 세션 설정이 유지되는 실제 Streamlit 합성 검사를 포함해 관련 검사 42개가 통과했다. 기본 설정 파일 변경은 사용자 선택 후 별도로 수행한다.

HTTP 실패 진단 보완: 그래프 해설의 비정상 HTTP 응답은 상태 코드를 보존하고 오류 본문을 최대 8 KiB까지 로컬에서 읽어 고정 사유로만 분류한다. 문맥 길이 초과·메모리 부족·이미지 미지원·404·접근 거부·서버 오류 등을 구분하며, 본문·서버 경로·프롬프트·자유형 오류 문자열은 UI나 명령 기록에 남기지 않는다. 200 응답의 압축 방식 거부는 별도 코드로 구분한다. 이 보완은 진단 기능이며 기존 `COMMENTARY_HTTP_REJECTED` 기록의 원인을 소급 복원하거나 문제 자체를 해결한 것은 아니다. 실제 원인은 사용자가 새 해설 요청의 HTTP 상태·고정 분류를 확인한 뒤 판단한다. 자동 재시도·모델 설정 변경·전처리 재실행은 없다.

단순 분할 표에 대한 후속 조정: 관찰 3개는 최대치일 뿐 채워야 하는 수가 아니다. 행 수·비율만 있는 단순 표는 한 문장으로 요약하고, 나머지 합계나 7:3 같은 재표현으로 관찰을 늘리지 않도록 지시한다. 세 구간을 유지하고, 자료에 없는 목표 비율 달성·분할 불균일 평가는 붙이지 않도록 한다. 이 변경은 프롬프트 지침이며 의미상 중복을 결정적으로 거부하는 검증기나 실제 모델 품질 보증이 아니다.

해설 표현 보완: 관찰은 서로 다른 핵심 사실 1~3개, 해석 한계는 실제 해석에 필요한 경우에만 0~2개로 제한한다. 한계가 없으면 빈 배열을 허용하며, 단순 계산 미수행·출처 부재 일반론을 억지로 나열하지 않도록 지시한다. 반올림 가능성을 무시한 오류 단정과 전달되지 않은 그래프의 관찰 주장을 금지한다. 공백만 다른 동일 문장은 표시 전에 중복 제거하지만 의미상 중복·수학적 정확성을 보증하는 검증기는 아니다. 완료된 해설도 별도의 새 요청 준비·재확인으로 다시 요청할 수 있다. 기존 응답·완료 작업을 자동 갱신하지 않는다. 합성 해설·UI 설정 검사 36개가 통과했으며 실제 모델 답변 품질은 사용자 확인이 필요하다.

전달 확인을 체크하지 않고 요청하면 안내한다. 실패·중복·응답 불명 상태에서는 기존 요청 버튼을 비활성화하고, 사용자가 이전 요청의 처리 가능성을 확인한 뒤 `새 해설 요청 준비`를 선택하게 한다. 이 버튼은 새 요청 ID만 만들며 모델을 호출하지 않는다. 실제 자료 전달은 새 폼에서 다시 확인해야 한다. 기존 명령·전처리·완료 결과를 삭제하거나 자동 재실행하지 않는다.

연결·시간 초과·응답 형식·정상 완료 여부 등은 고정 오류 코드로 표시한다. 예외·응답·데이터 원문은 표시하지 않는다. 과거 실패 기록에는 진단 코드가 없을 수 있어 소급하여 원인을 단정하지 않는다. 보완 후 합성 해설·UI 설정 검사 33개가 통과했으며 실제 모델 요청을 재전송하지 않았다.

아래는 2026-10-18 시점의 합의와 후속 범위를 보존한 기록이다. 현재 동작은 위의 구현 절을 우선하며, 설계 문서를 읽거나 결과를 열람하는 것만으로 실제 자료 전달에 동의한 것으로 간주하지 않는다.

## 0. 확정한 사용 흐름 — 2026-10-18

사용자는 **설정 화면에서 기본 허용 범위를 정하고, 해설받을 자료를 선택한 뒤 실제 전송 내용을 확인하여 전송**하는 방식에 동의했다. 설정 저장만으로 전송하지 않는다.

```text
설정: 사용 목적·대상 모델별 허용 항목 저장
                     ↓ 실제 전송 없음
결과: 해설받을 표·집계·그림 선택
                     ↓ 허용 범위·지원 기능 검사
전송 미리보기: 실제 전달 내용·수신 대상·추측 위험 확인
                     ↓ 사용자가 [전송하고 해설받기] 선택
전송 직전: 정책·모델·자료·내용의 일치와 승인 유효성 재검증
                     ↓ 일치한 요청에 한해 1회 전송
결과: LLM 해설 표시 — 실행 승인·품질 판정으로 사용하지 않음
```

정책에서 허용하지 않은 항목은 선택·전송을 차단한다. 일부 항목을 제외할 수는 있지만, 제외 사실과 최종 전송 내용을 반드시 미리보기에 표시한다. 확인 뒤 몰래 추가·제외·치환하지 않는다. 로컬 UI에서 표·그림을 열어보는 것은 LLM 전송과 별개이며, 설정 허용이나 열람을 전송 동의로 간주하지 않는다.

LLM 정보 전달 승인·전처리 실행 승인·LangSmith 추적 허용·대화 저장 설정은 서로 별개다. 대상 모델이 로컬인지 외부 API인지도 UI 서버가 로컬인지와 구분한다.

## 1. 사용자 제안과 목표

사용자가 선택한 모듈로 EDA·검사·변환 파이프라인을 만들고, 필요하면 LLM이 표·그림 아래에 간략한 해설을 붙인다. 2026-10-18 사용자 결정 방향은 일괄 보안 등급보다 기능별로 전달 항목을 선택하고 실제 전송 내용을 확인·허용하는 방식이다. 사용자는 허용한 정보에서 생길 추측 위험을 인지하고 선택하며, 시스템은 승인 범위를 넘겨 보내지 않도록 강제한다. 이는 현재 실제 데이터 전송을 허용하거나 해당 기능이 구현됐다는 뜻은 아니다.

LLM의 기본 역할은 자연어 요청 해석·등록 모듈 설명·실행안 제안·설정 안내·진행 상태 설명이다. 실제 데이터 기반 해설은 별도 정보 전달 계약과 승인 기능을 구현·검증한 경우에만 선택적으로 추가한다. 전처리 계산은 등록된 코어/worker가 수행하며 LLM 없이도 같은 파이프라인이 동작해야 한다.

## 2. 검토 시작의 선행 조건

- [x] 등록된 내장 모듈 범위의 공통 계약과 표형·WM 통합 등록부 정비.
- [x] 지원하는 표형·WM 파이프라인 설정과 입력/출력·순서·의존성 검증 구현.
- [x] 내장 EDA·품질 코어의 모듈 재사용과 기존 승인·격리 실행·결과 검증 연결.
- [ ] 모듈별 보고서 출력 계약에 그래프/표의 의미·단위·판정 근거·해석 한계 정의.
- [ ] 규칙 기반 실행과 로컬 해설만으로 정상·실패·검토·취소 경로 검증.

현재 통합 등록부, 지원 모듈의 설정·조합 검증, 표형 모듈 실행과 WM 정상 6단계의 공통 생성·배정·승인·실행을 구현했다. 사용자 모듈은 검토된 참조 모듈의 합성 실행 범위이며 임의 코드·모든 형식의 자유 조합을 지원하지 않는다. 로컬 Qwen·LangChain·LangGraph의 질문·답변에서 제안 저장·복원·입력 결합·별도 승인·합성 정상/품질 검토 중단 경로까지 확인했다. 선택형 공개 제어 계층·실제 결과 해설은 아직 구현하지 않았다. 개별 worker마다 LLM 호출을 중복 추가하지 않는다. 최신 범위는 [구현 안내](../GUIDE.md)를 따른다.

## 3. 해설의 두 종류

| 구분 | 정보와 생성 방식 | 표현 원칙 |
| --- | --- | --- |
| 읽는 방법·일반 설명 | 검토된 모듈 설명·그래프 종류·지표 의미만으로 LLM 또는 고정 템플릿 작성 | 실제 데이터를 확인한 결론처럼 표현하지 않음 |
| 이번 결과의 관찰 | 로컬 규칙으로 생성하거나 별도 승인한 집계 DTO를 LLM에 전달 | 관측·가설·해석 한계를 구분하고 원인/인과를 단정하지 않음 |

예시: 결측률 그래프의 축·막대 의미는 데이터 없이 설명할 수 있다. 실제 기준 초과 여부·컬럼·건수는 로컬 결과로 작성한다. 상세 수치를 로컬에서만 삽입하는 방식에서는 완성된 문장을 LLM에 다시 보내지 않는다.

모듈별 출력의 목표 구성은 `표·그림 / 읽는 방법 / 이번 결과 해설 / 주의사항`이다. LLM 해설이 없어도 보고서가 정상 생성돼야 한다.

첫 버전의 선택 범위에서도 원본 파일·원본 행·샘플·배열·웨이퍼 이미지·실제 경로·원문 예외·전체 실행 로그는 제외한다. 비밀 키·인증정보·승인 토큰·승인 DB는 분석 정보 공개 설정으로 허용하지 않는다. 원본 전달 지원은 기존 원칙을 변경하는 별도 설계가 필요하다. 그래프를 허용했다고 원본 웨이퍼 이미지를 전달할 수 있는 것은 아니다.

표의 컬럼 헤더·셀, 그래프의 제목·축·범례·부가정보에도 식별명·수치·경로가 들어갈 수 있다. 상위 항목 허용이 다른 항목의 차단을 무효화하지 않도록 교차 검사한다. 예를 들어 표 허용·실제 컬럼명 차단이면 이름을 그대로 전송할 수 없고, 검토된 대체 표현을 미리 보여 주거나 전송을 차단한다. 임의 자유 텍스트·원본 행이 섞인 표는 등록된 결과 표로 추정하지 않는다.

집계도 센서명·공장명·라벨 비율·정확한 건수·시간별 변화 등으로 정보를 추측하게 할 수 있다. 식별자 제거·익명화·반올림·높음/낮음 변환이 추측 불가능함을 보증하지 않는다. UI는 남는 위험을 표시하고 사용자는 실제 내용을 확인한다. 사용자 선택이 시스템의 범위 강제 책임을 없애지는 않는다. 자유 문장의 민감정보를 모두 자동 탐지할 수 있다고 주장하지 않는다.

### 4.3 설정·결과 화면의 책임

- 설정 화면: 대상·목적별 허용 항목을 편집하고 `[기본 정책 저장]`으로 저장한다. 동작은 로컬 정책 저장뿐이며 기존 자료·대화를 자동 전송하지 않는다.
- 결과 화면: 지원하고 허용된 해설 자료를 선택한다. 미지원·금지 항목은 이유와 함께 선택을 차단한다. 승인 DB나 자유 파일 경로를 선택 대상으로 제공하지 않는다.
- 전송 확인 화면: 대상 모델·목적·정책 버전·선택 자료·제외/변환 내역·실제 요청 내용을 표시하고 `[전송하고 해설받기]` 확인을 받는다. 원본 파일을 열어 보는 것과 다르다.
- 내용이 바뀌면 이전 미리보기·전송 확인을 무효화한다. 모델 구성·수신 대상·정책 버전·선택 자료·행/열 범위·본문 변경은 새 미리보기와 새 확인이 필요하다. UI 상태만 믿지 않고 전송 직전 서비스 계층에서 검사한다.

첫 화면에 체크박스를 표시하는 것만으로 기능 구현 완료라고 간주하지 않는다. 양식·정책·전송 확인·제공업체 경계·응답/로그 처리가 연결되고 검증된 항목만 활성화한다.

## 5. 전송 승인·격리 경계

1. 결과를 읽는 신뢰된 로컬 축소기가 등록된 해설 양식의 필드만 추출한다. 임의 표 전체·그림·보고서 원문을 자동 첨부하지 않는다.
2. 보내려는 정확한 payload와 수신 대상(로컬/외부·provider·endpoint·모델)을 로컬에서 미리 보여 준다.
3. 사용자 승인은 실행·결과 묶음·양식 버전·payload 내용 식별값·수신 대상·유효기간·사용 횟수에 결합한다. UI 확인 문구만으로 기존 처리 승인을 전송 승인으로 간주하지 않는다.
4. 정책 버전·모델 구성·필드·선택 자료·내용·수신 대상 변경은 재확인을 요구한다. 확인 후 payload를 더 상세하게 바꾸지 않는다. 승인 만료·이중 클릭·재사용·동시 요청도 서버 측에서 검사하고 전송 승인은 1회 소비한다.
5. 전처리 worker는 외부 통신을 계속 금지한다. 선택적으로 허용하는 LLM 연결은 별도 권한·egress 경계에서 축소 payload만 받는다.
6. 로컬 endpoint 검증 실패·응답 장애 시 외부 API로 자동 전환하지 않는다. 전송 시도 후 응답을 못 받았어도 미전송이라고 단정하지 않으며 자동 재시도하지 않는다. 재전송하려면 새 확인이 필요하다. LLM 미사용 또는 출처가 구분된 고정 로컬 해설로 중단/복귀한다.
7. 전송·해설 승인은 삭제·변환·모듈 등록 승인을 대신하지 않는다. Train-only·누수 방지·임의 코드 실행 금지·Job 제한도 완화하지 않는다.

해시·승인 기록은 내용 일치 확인을 위한 것이며 익명성이나 안전성을 인증하지 않는다. 기존 승인 API의 재사용 가능 범위와 해설 전용 승인 계약의 필요성을 설계 때 검토한다.

## 6. LLM 응답과 이력 관리

- LLM 출력은 해설 텍스트만 허용한다. 셸 명령·함수 실행·동적 모듈 등록·정책 변경으로 해석하지 않는다.
- 출력 길이·필드·형식을 제한하고 요청에 없는 수치·센서명·원인 단정 등 근거 없는 주장을 검토한다. 완벽한 사실성 보증은 주장하지 않는다.
- 로컬 결과의 문자열은 지시문이 아닌 데이터로 취급한다. 가능하면 첫 버전은 자유 텍스트 필드를 제외한다.
- 사용 모델·모드·양식 버전·승인 참조·성공/실패와 로컬 생성 설명인지 LLM 설명인지 구분한다.
- 감사 로그·오류·SDK tracing·LangSmith·자동 업로드·telemetry에 프롬프트/집계/응답이 복사되지 않는지 검증한다. 해시만 남기는 경우에도 보존·접근 정책을 정한다.
- 전송 후 승인을 취소해도 이미 외부로 보낸 정보를 회수할 수 있다는 보장은 하지 않는다. provider의 보존·학습 사용·삭제 조건은 선택 시 별도로 확인한다.

## 7. 추가 구현 범위와 단계

| 기능 묶음 | 추가 작업 |
| --- | --- |
| 항목별 정책 | 기본 거부, 목적·대상별 허용 양식·필드·수신 대상·정책 버전 |
| 해설 입력 생성 | 로컬 결과 축소·검증·버전 관리, 데이터 유래 자유 텍스트 제한 |
| 사용자 승인 | payload 미리보기·전송 전용 승인·변경/만료/재사용 거부 |
| LLM provider | 로컬/외부 연결·키 분리·timeout·비용/재시도 한도·안전한 fallback |
| 결과 표시 | 제한된 응답 검증·로컬 보고서 삽입·생성 방식/한계 표시 |
| 보안 검증 | 금지 필드 혼입·prompt injection·수신 대상 변경·로그 유출·응답 실패·승인 경쟁 |

설정 저장과 개별 전송 확인의 분리는 확정했다. 항목별 양식·제공업체 지원·구현 우선순위의 권장 순서는 다음과 같다.

1. 모듈형 rules-only 파이프라인과 로컬 결정적 해설 완성.
2. 데이터 없는 모듈/그래프 설명과 기본 차단 정책·전송 미리보기 연결.
3. 고정 집계 양식 **하나**의 미리보기·사용자 승인·해설 추가.
4. 로컬/외부 수신 대상의 별도 검증과 선택 범위 확대.
5. 임의 표·그림·자유 필드 전송은 초기 범위에서 제외하고 필요 시 새 보안 검토.

추가 규모는 설정 몇 개가 아니라 별도의 정보 전달·승인·검증 기능 묶음이다. UI/CLI 수준·provider·허용 양식이 정해지기 전에는 기간을 단정하지 않는다. 기존 snapshot·worker·승인 기반을 재사용하되 모두 다시 구현하지 않는다.
