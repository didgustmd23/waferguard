# 검토된 CSV 모듈의 범용 파이프라인 연결 설계

작성일: 2026-10-17. 다음 구현의 입력·등록·실행·결과 계약을 정의한다. **이 문서는 실데이터 실행 승인이나 기능 활성화가 아니다.** 기존 합성 전용 worker의 입력 제한을 단순히 제거하지 않는다.

## 1. 출발점과 목표

사용자 제공 실행 결과에서 `reviewed-module01`의 `completed / module_status: passed / synthetic_only: true`를 확인했다. 작업 ID는 `c0f6841b7f7d4b40a76a514d4dbaeaa0`다. 이는 고정 합성 CSV와 참조 모듈 하나의 Windows 격리 실행 확인이며 일반 사용자 코드·실데이터 사용 승인과는 다르다.

목표는 사용자 선택의 CSV snapshot·프로파일·모듈 계획을 검토된 고정 등록부와 결합해 승인 후 실행하는 것이다. 모듈마다 새 CLI를 계속 추가하지 않고 하나의 CSV 모듈 실행 관리자가 ID·버전별 고정 구현을 선택한다.

첫 연결 대상은 `user_missing_row_histogram`이다. 참조 계산은 이미 수치·범주 특징 목록을 입력 계약에서 받으므로 SECOM 센서명에 의존하지 않는다. 기존 명세의 `synthetic_local_only`를 수정하는 것만으로 일반 실행을 허용하지 않는다. 새 검토 범위·명세 해시·실행 정책·결과 검증기를 코드 검토와 테스트 후 함께 등록해야 한다.

## 2. 초기 지원 범위

| 구분 | 지원할 범위 | 초기 제외 |
| --- | --- | --- |
| 입력 | `tabular_csv_v1`, 검증한 snapshot·컬럼 역할 | pickle, 맵, 이미지, 네트워크 URL |
| 모듈 | 내장 품질 검사·EDA와 명시적으로 연결한 검토 모듈 | 임의 Python 경로·폴더 자동 검색·pip 자동 설치 |
| 종류 | 비파괴 analysis·validation | 사용자 변환·분할·모델 학습 |
| 연결 | 모든 단계가 같은 `source.data`를 분석 | 앞 단계의 DataFrame을 다음 단계로 전달 |
| 승인 | 정확한 전체 목록·입력·설정·코드·자원에 새 승인 | 합성 실행 승인 재사용·LLM 승인 |
| 결과 | 로컬의 고정 CSV·JSON·Markdown 계약 | 자동 공유·외부 추적·LLM 해설 전송 |

비파괴 분석만 한 작업에 묶는다. 기존 전처리의 기준 산출 → 후보 검토 → 별도 적용 승인 경계는 합치지 않는다. 지원하지 않는 연결은 계획 생성 시 거부한다.

## 3. 현재 코드와 필요한 변경

| 현재 위치 | 현재 제한 | 다음 구현에서 필요한 처리 |
| --- | --- | --- |
| `module_catalogue.py` | 고정 참조 명세 1개, 합성 범위 | 코드 검토로 선택하는 실제 CSV 분석 범위·명세 엔트리 추가 |
| `build_reviewed_registry()` | 개발용 초기화에서 참조 Python을 import | 부모 계획 검증은 계산 함수 없는 메타데이터 등록부 사용 |
| `module_pipeline_contract.py` | 내장 6개만 허용 | 검토된 엔트리·결과 계약이 연결된 모듈만 별도 실행 정책에서 허용 |
| `reviewed_module_contract.py` | 고정 fixture 해시·프로파일 | 일반 snapshot·역할·파이프라인·등록 명세·자원 결합 |
| `reviewed_module_worker.py` | 고정 CSV 8행, 모듈 1개 | 승인된 순차 목록 실행·품질 중단·범용 CSV 읽기 |
| `reviewed_module_results.py` | 8행과 `(0,7),(1,1)` 정답 | 파일·헤더·정수·범위·집계 일관성 검사로 분리 |

기존 합성 경로는 회귀 검증용으로 보존한다. 공통 소스 변경으로 코드 식별값이 달라지면 기존 승인으로 재실행하지 않는다. 과거 완료 파일·승인 DB를 현재 코드에 맞게 덮어쓰거나 자동 재실행하지 않는다.

## 4. 부모와 worker의 역할 분리

```text
사용자: snapshot + 프로파일 + 모듈 계획 + 자원 한도 선택
    ↓
부모: 고정 명세·코드 목록·설정 스키마·순서·결과 계약 검증
    ↓
사용자: 새 실행 승인
    ↓
AppContainer+Job: 허용 CSV 읽기 → 필수 품질 검사
    ├─ 검토 필요/차단 → 보고서 보존·중단
    └─ 통과 → 검토된 모듈만 순차 import·계산·결과 저장
    ↓
부모: 종료·정리 증거 + 고정 결과 파일 검증
    ↓
통과하면 커밋 / 실패·취소면 미완료로 보존
```

부모는 사용자 모듈의 계산·설정 검증·메모리 결과 검증 함수를 호출하지 않는다. 현재 `validate_pipeline(config, registry)`는 등록 객체의 validate_settings를 호출하므로, 사용자 Python 콜백이 아니라 **신뢰된 JSON 설정 검증기**를 가진 메타데이터 등록부를 전달한다. 기존 계획 검증기의 계약·포트·순서 검사는 재사용한다.

첫 설정 스키마는 bool·범위가 있는 정수/유한 수·길이가 제한된 문자열·enum과 명시 기본값만 지원한다. 알 수 없는 키·잘못된 타입·과대 설정은 거부한다. 참조 모듈은 include_complete를 bool/default true로 선언한다. 스키마 표현식·함수 경로·eval은 제공하지 않는다.

worker 안에서도 승인한 정규화 설정을 다시 검증한다. 모듈의 설정 검증 결과가 승인한 설정과 다르면 자동 보정하거나 계속 실행하지 않는다. 품질 미통과 때는 사용자 모듈 import 자체를 하지 않는다.

## 5. 입력·분할·품질 조건

- 기존 `bind_eda_input`의 파일 크기·snapshot 해시·adapter·역할 계약을 재사용한다. 선택한 복사본만 worker에 전달하고 원본 폴더·승인 DB 권한은 추가하지 않는다.
- 라벨·ID·그룹·시간을 분석 특징과 분리한다. 컬럼 누락·중복·잘못된 수치·CSV 구조 오류를 조용히 보정하지 않는다.
- 새 실행 정책에서는 품질 검사를 첫 단계에 정확히 한 번 요구한다. 후속 모듈은 품질 통과에 의존한다. review_required·blocked_input을 자동으로 ignore로 바꾸지 않는다.
- 품질 규칙은 프로파일을 기본으로 결합하고 명시 변경을 승인 화면에 표시한다. 정책 위반을 감추는 우회 옵션은 추가하지 않는다.
- 단순 CSV의 train 선언은 확정 분할 증거가 아니다. 분할 증거가 없는 snapshot은 unsplit 분석 입력으로 취급한다. Train/Validation 역할을 보증하려면 기존 확정 분할·구간 입력 계약을 결합해야 한다.
- 알려진 Test 계약의 분석은 첫 범위에서 제외한다. 사용자가 임의 CSV를 선택한 경우 과거 사용 여부나 숨겨진 Test 여부를 파일명만으로 증명할 수 있다고 주장하지 않는다.
- 작업별 파일/행/컬럼·출력 상한을 설정하고, 초과 시 자르거나 일부만 분석해 성공하지 않는다. Job 메모리·프로세스 수·시간 한도는 전체 작업에 적용한다.

## 6. 등록·승인·코드 복사

실행 가능 여부는 사용자 JSON의 reviewed/approved 값이 아니라 코드에 고정한 등록 엔트리에서 결정한다. 엔트리에는 명세 ID/해시·모듈 ID/버전·전체 로컬 의존 파일·고정 구현·설정 스키마·결과 계약·허용 종류와 권한 범위를 결합한다.

기존 합성 엔트리는 유지하고 실제 CSV용 검토 범위를 별도로 추가한다. 명세 revision과 실행 정책 식별값을 새로 지정한다. 계산 동작을 바꾸면 모듈 버전도 올린다. 임의 명세 경로·Python import 문자열을 사용자 설정에서 받지 않는다.

실행 승인에는 입력 계약·유효 프로파일/품질 규칙·단계 순서/입력 연결·모듈 버전·정규화 설정·명세 식별값·코드 파일 목록/해시·자원/출력 한도를 함께 결합한다. 등록 승인은 실행 승인을 대신하지 않는다.

운송 계층은 선택한 검토 모듈과 허용 의존 코드만 복사하고 원시 바이트 해시를 대조한다. 등록 검사에서 사용하는 LF 정규화 해시와 운영 복사/승인 해시는 목적을 구분한다. worker의 경로 검사는 고정 tools/input 하위에 한정하며 접근 권한을 넓혀 조상 폴더를 조회하는 방식으로 해결하지 않는다.

## 7. 결과 계약과 검증 한계

새 참조 CSV 결과 계약의 제안 ID는 `missing_row_histogram_csv_v1`이다. 아직 등록된 운영 결과 계약은 아니다. 출력 파일은 고정 basename·헤더·인코딩·최대 바이트·필수 컬럼과 값 범위를 선언한다. 임의 부모 검증 함수를 명세에서 import하지 않는다. 새 형식은 신뢰된 부모 검증 코드·합성 테스트를 별도로 추가해야 한다.

행 결측 분포에서 부모가 검사할 항목은 다음과 같다.

- missing_feature_count는 중복 없는 오름차순 정수, 범위는 0~승인된 특징 수.
- row_count는 양의 정수, 각 값과 합계는 승인한 입력 행 상한 이내.
- include_complete=true이면 빈도 합계는 worker 보고의 입력 행 수와 일치.
- include_complete=false이면 0 항목이 없고 빈도 합계는 보고 행 수 이하. 결측 없는 행은 집계에서 제외되므로 같을 필요는 없음.
- 결과 단계·파일은 승인한 계획의 완료 prefix와 정확히 일치. 품질 중단 뒤 생성한 후속 결과와 부분 성공 주장은 거부.
- 프로세스 종료·활성 프로세스 0·Job/프로필 정리·요청/응답·입력 불변성을 기존 방식으로 검증.

합성 정답 `(0,7),(1,1)`과 고정 8행 검사는 기존 합성 경로에서만 유지한다. 일반 CSV에서는 부모가 원본을 다시 읽거나 같은 사용자 계산을 재실행하지 않는다. 따라서 worker 보고 행 수와 집계가 일관적인지는 검사할 수 있지만 원본 대비 모든 계산의 정답을 독립 인증하지 않는다. 해시도 로컬 관리자의 동시 변조에 대한 진본 인증이 아니다. LLM 검증은 추가하지 않는다.

## 8. 구현 순서와 완료 기준

1. **메타데이터 등록부·설정 스키마:** 사용자 Python을 import하지 않고 명세만으로 계획을 검증한다. 다음 실제 구현의 첫 작업이다.
2. **CSV 실행 계약 결합:** snapshot·프로파일·품질 우선 순서·지원 모듈/출력 계약·승인 인자를 결합한다. 실행 명령은 아직 활성화하지 않는다.
3. **worker·운송·부모 검증 연결:** 합성 전용 코드의 제한을 삭제하는 대신 범용 CSV 경로를 별도 정책으로 구현한다.
4. **합성 회귀 검증:** 컬럼/역할/타입이 다른 CSV, target 없는 입력, 결측 없는 입력, include_complete 두 설정, 품질 중단, 코드/명세/설정 변경, 파일/정수 범위 변조, 자원 초과, 취소, 복사 패키지 부팅을 확인한다.
5. **사용자 Windows 합성 확인:** 정상·중단 상태와 요청/종료/정리 증거를 확인한다.
6. **실제 CSV 기능 확인:** 사용자가 선택한 개발 데이터로 새 실행·새 승인을 받는다. SECOM은 검증 사례일 뿐이며 기존 ML 모델·분할·Test·결과는 덮어쓰지 않는다.

첫 완료 목표는 검토된 참조 모듈 하나와 내장 품질/EDA를 사용자가 순서·설정으로 선택하고, 승인된 CSV 복사본에서 실행할 수 있는 것이다. 임의 코드 업로드·사용자 변환·모델 학습·LLM 기능·맵/이미지 확장은 별도 후속 범위다.
