# 전처리 에이전트 사용 안내

현재 사용법·지원 상태·제한의 진입점이다. 구조와 계약의 유일한 설계 기준은 [DESIGN](DESIGN.md)이다. 과거 변경/실행 이력은 Git과 로컬 테스트·작업 로그에서 확인한다.

## 현재 구현 상태

| 범위 | 상태 |
| --- | --- |
| 통합 작업 | 공통 조정기·표형(CSV) 어댑터 구현. 진단 → 권장안/질문 → 계획 → 분할·전처리 → 적용·전달 → 보고서 연결 |
| 배열 통합 작업 | `.npz` 배열 어댑터 구현. 매핑(표본·채널 축·라벨·그룹·ID) → 메타데이터 기준 분할 → Train 채널 기준 → Train·Validation float32 결과. 합성 입력의 실제 AppContainer·Job 실행, 실제 로컬 모델 요청, 사용자 화면 확인 이력이 있다. 입력 미리보기는 로컬 전용. 옵션이 모두 none이어도 float32라 반올림·값 합쳐짐이 생길 수 있다. 대용량 처리를 보장하지 않으며, 최신 bool 라벨 보완의 실제 OS 실행은 미확인이다. 검증 범위는 아래를 따른다 |
| 실패 대응 | 중복 헤더 동의형 정비, 품질 지적 표시, 일부 입력 실패의 계획 수정·새 시도, 완료 저장 실패의 검증 후 복구 |
| 결과 설명 | 전체 옵션 편집·설명, 후보 영향, 출처·제외 사유, 예상/실측 구분. Test 미적용·미처리·미검증 표시 |
| 메뉴 | 기본은 통합 작업의 작업/설정. 기존 LLM 제안·등록 모듈은 고급 도구에 유지. 사용자 화면 확인 완료 |
| 기존 도구 | CSV 5개 작업, WM 정상 개발 6단계, 구조 판별 pickle 변환, 저장 EDA 제안 목록 복원·모델 목록 조회·별도 로컬 결과 해설 |
| 미지원 확장 | pickle·이미지 폴더 배열 입력, 웨이퍼 통합 프로파일, 통합 time 분할, 외부 API, 일반 자동 재개/사용자 코드 실행 |

구현·테스트 통과·실제 환경 확인은 다르다. CSV 실제 작업의 완료 이력이 있지만 모든 데이터·설정의 적절성이나 모델 성능을 보장하지 않는다. 기존 SECOM 실험과 통합 작업은 입력·분할·전처리 설정을 맞추지 않으면 동일 실험이 아니다.

현재 로컬 모델은 확인한 사례에서 진단 수치 해석, 라벨·그룹 구분, 전처리 권장 이유에 오류가 있었다. 형식·허용값 검사를 통과해도 내용의 타당성을 보장하지 않으므로 계산 결과와 모델 의견을 구분해 확인한다. 이는 현재 모델의 관찰된 한계이지 에이전트 공통 기능의 제한이 아니다. 다른 로컬·API 모델은 별도 품질 평가가 필요하며, 외부 API 연결은 현재 미지원이다.

## 시작하기

프로젝트 루트와 Windows Python 3.12 환경을 사용한다.

```powershell
conda activate wm-gpu312
Set-Location D:\workspace\waferguard
python -m streamlit run src/ui/app.py --server.address 127.0.0.1
```

실제 UI 격리 실행의 권한 안내를 확인한다. 관리자 권한이 필요한 경로는 관리자 PowerShell에서 서버를 시작한다. 모든 조회·합성 회귀에 관리자 권한이 필요한 것은 아니다. 코드 변경 후 서버를 다시 시작한다. 설정 → 연결 확인은 Ollama `/api/tags` 목록 조회이며 추론/모델 품질 검사가 아니다.

### 통합 작업

1. 파일(CSV 또는 `.npz`)과 목표를 입력하고 작업/복사·진단·모델 전달 범위를 확인한다. 목표에 예측 대상을 명확히 적는다. `.npz`는 pickle 없이 숫자·bool·문자열 배열만 읽고, 모델에는 라벨 이름 대신 순번별 개수만 보낸다(클래스 의미 해석 불가).
   - `.npz`는 진단 화면에서 입력 미리보기(앞쪽 최대 12개, 로컬 전용)를 보고 표본 배열·채널 축·라벨·그룹·ID를 매핑한다. 같은 표본이 있으면 '같은 표본을 한 구간에 모으기'로 누수를 막을 수 있다(삭제 없음).
2. 격리 진단 후 모델 권장안 출처와 질문을 확인한다. 모델 실패 시 기본 계획으로 표시되며 자동으로 재요청하지 않는다.
3. 중복 헤더로 막히면 동의한 경우에만 번호 붙인 복사본으로 진행한다. 원본과 데이터 값/순서는 유지한다. 빈 이름 등은 자동 수정하지 않는다.
4. 역할·분할·전처리 옵션을 수정한다. target·식별자를 확인하고 필수 질문에 답한다. 비예측 목적이면 예측 대상 없음에 명시적으로 답한다. 질문과 양식 충돌은 직접 선택한다.
5. 최종 계획 미리보기의 유효 설정을 확인하고 동의 C로 분할·내보내기·후보까지 진행한다. 내부 실행명·선행 결과는 시스템이 연결한다.
6. 후보의 제거·출력 폭·clipping·상수화 경고를 확인한다. 바꾸려면 적용하지 않고 계획 수정으로 새 시도를 준비한다. 그대로 적용할 때 동의 D로 적용·전달을 진행한다.
7. 결과의 실제 처리·전후 비교·미처리/미검증·파일 활용을 확인한다. 완료는 전처리 완료이지 모델 성능 검증이 아니다.

동의 A/C/D의 정확한 범위는 [설계](DESIGN.md#승인과-실행)를 따른다. 기존 동의를 다른 입력·계획·시도에 재사용하지 않는다. 화면 갱신·메뉴 전환은 새 모델 호출·승인·worker 실행의 동의가 아니다.

### 옵션과 품질 지적

- 구간화·스케일링·이상치 처리는 필요에 맞게 끌 수 있다. 모델 질문이 없어도 양식에서 수정 가능하다. 허용되지 않은 조합은 자동 수정하지 않고 충돌을 표시한다.
- 상수나 결측이 많은 컬럼은 진단 근거를 보고 역할을 정한다. 분할 전 품질 기준과 Train 전처리 제거 기준은 별개다. 일괄 제외는 직접 선택할 때만 적용한다.
- IQR 후보는 정상 0/1 값일 수도 있다. 후보 수만으로 삭제/clipping을 결정하지 않는다. 적용 전 정보 손실 경고를 확인한다.
- 숫자 문자열/공백을 수치형으로 정비하거나 조건부 대치하는 기능은 아직 없다. 현재는 적합한 역할/제외를 선택하거나 별도 입력 정비를 준비해야 한다. 원본 수정 명령을 자동 실행하지 않는다.

### 결과 파일 사용

전처리 기준은 Train에서만 산출하고 Train·Validation에 적용한다. 결과는 학습 특징 파일과 같은 순서의 `rows.json`에 target·식별자·출처를 나눠 보존한다. `feature_mapping.json`은 출력 열과 원본 특징의 대응, `preprocessor.json`은 Train 기준, `application.json`은 적용·검증 기록이다.

Test는 변환하지 않는다. Test/새 데이터에는 저장한 Train 기준을 별도로 적용해야 하며, 통합 작업이 그 실행이나 성능 평가까지 끝냈다고 보지 않는다. Validation에 새 범주가 있으면 `unknown_category=error` 설정은 차단될 수 있다. 전달 묶음은 [CSV_HANDOFF](guides/CSV_HANDOFF.md)의 검증 절차로 독립 확인할 수 있다.

## 문제 발생과 기존 작업

- 먼저 확인된 worker 분류·세부 코드와 추정 원인을 구분해 읽는다. 자동 재시도하지 않는다.
- 일부 결정 C 입력 실패/적용 전 후보는 계획 수정 후 새 동의·새 시도로 진행할 수 있다. 환경 오류·불명확 실행·D 이후를 같은 방식으로 재시도할 수 있다는 뜻은 아니다.
- 계산은 끝났지만 완료 저장만 실패했다면 검증 후 완료 기록 복구를 사용한다. worker·승인을 다시 실행하지 않고 계보·결과를 검증해 기록만 복구한다.
- 코드가 바뀌면 미실행 승인이 무효가 될 수 있다. 완료 파일은 보존하지만 모든 과거 결과를 현재 검증기로 열 수 있는 것은 아니다. 코드 변경 후 handoff 읽기 전용 검증은 제한적으로 지원한다.
- 기록 크기·파일 없음·소유자·해시/링크 오류를 구분한다. 파일을 임의 수정하거나 승인 소비를 되돌려 해결하지 않는다.
- 화면이 오래 멈추면 `events.jsonl`의 마지막 started/finished와 프로세스를 확인한다. 터미널 텍스트 선택으로 출력/실행이 일시 정지될 수도 있으나 추측으로 단정하지 않는다.

## 검증 상태와 남은 제한

최신 전체 회귀 근거는 `logs/agents/regression/3dd90d5127f9409f97682e554038c768/summary.json`이다. **1149개 실행·1136개 통과·실패 0·오류 0·생략 13, status=passed**, 경과 2692.263초다. 생략은 실제 Windows 격리 선택 검사 12개와 심볼릭 링크 생성 권한 1개다. 품질 검토와 적용 전 계획 수정의 간헐 실패 테스트도 실행돼 통과했지만 원인 해결의 증거로 보지 않는다. 이전 `ea687d47fbf943d8b30a116a3db1acda`의 실패 기록은 당시 결과 그대로 보존한다.

위 전체 회귀 이후 bool 라벨을 입력에서는 허용하지만 적용 결과에서 거부하던 검증기를 보완했다. 수정 전 실패를 재현했고, 수정 후 배열 전체·합성 공통 어댑터·메뉴 관련 31개 테스트가 실패·오류·생략 없이 통과했다. bool 라벨의 타입·값·표본 순서 보존과 기존 중첩 객체·배열·비유한 수·길이 초과 문자열 거부를 확인했다. 이 검사는 합성 입력·모의 OS 운송·모의 모델 기준이다. **bool 보완까지 포함한 코드 전체의 회귀는 아직 재실행하지 않았다.** 배열 코드 지문이 바뀌어 기존 미실행 배열 승인은 다시 준비해야 하고, 기존 배열 실행 조회도 지문 검사로 거부될 수 있다. 기존 결과 파일은 보존하며 CSV·모듈 파이프라인 코드 지문은 이 보완으로 바뀌지 않았다.

배열 실제 확인은 합성 작업 `94197a0358a943dea83434dd025a697e`의 진단·후보·적용 AppContainer 정상 종료, Job 제한·정리와 별도 NumPy 계산 대조(사용자 제공 확인 스크립트 29항목 통과), 사용자 화면 조작 이력이다. 후속 작업 `f04e263a142f4321a19f73bf0594468d`도 같은 입력·계획으로 완료됐고, 저장 기록·보고서 해시를 대조했다(후속 작업의 출력 배열 독립 재계산은 하지 않음). 실제 로컬 모델 요청은 확인했지만 의미 오류가 남아 있으며 모델 품질 검증 완료로 보지 않는다. 모델 한계 안내의 실제 화면 표시는 사용자 확인 완료다. 이 확인들은 bool 보완 전 기준이며 모든 설정·실데이터·최신 코드의 실제 OS 실행을 보장하지 않는다.

남아 있는 제한:

- 품질 검토 테스트의 간헐 PROCESSING_FAILED는 원인 미확인이다. 이번 회귀에서 해당 오류가 없다고 해결로 보지 않는다.
- 적용 전 계획 수정 테스트의 다중 모듈 실행 실패는 후속 재현 검사에서 재현되지 않았다. 원인은 미확인이며, 실패 시 작업 상태·문제·단계 기록이 나오도록 테스트 진단만 보강했다. 위 품질 검토 실패와 같은 원인이라고 단정하지 않는다.
- 모델의 내용 오류와 실제 문맥 잘림 감지는 별도 문제다. 예산·응답 계약 통과가 의미적 권장안 품질을 보장하지 않는다.
- 배열의 실제 egress 차단은 위 실행·회귀로 증명되지 않았다. 부모 검증기의 배열 전체 적재에 따른 메모리 사용과 2 GiB 근처 입력의 동작도 미검증이다.
- API의 일부 미리보기/적용 기대값이 선택 인자인 상태다. 현재 화면 호출은 전달하며 서버 필수화는 후속이다.
- 특징별 영향·clipping 수 등 원본과 독립 대조하지 않은 worker 통계는 검증 범위를 표시한다.
- 큰 재시도 이력/내용의 크기 상한과 참조되지 않는 분리 파일의 수동 정리 정책은 남아 있다. 자동 삭제하지 않는다.
- 일반 재접속·백그라운드 취소/복구, 모든 과거 단계의 읽기 전용 검증은 지원하지 않는다.
- 개인 테스트 선택기는 참고용이며 낮음 지적 4건은 보류다. 프로젝트 완료 판정 근거로 사용하지 않는다.

후속 순서는 [설계의 후속 범위](DESIGN.md#후속-범위)를 따른다. 사용법·계약·지원 범위가 바뀔 때 해당 문서만 갱신하며 날짜별 작업 절·중복 검증 이력을 추가하지 않는다.
