# 제한 worker 실행 계약 — 1단계

후속 구현: 고정 합성 CSV에 한해 승인·예약 → AppContainer+Job → 부모 검증·완료 등록 경로를 추가하고 실제 정상 실행을 확인했다. [합성 격리 EDA 실행 기록](../history/ISOLATED_EDA.md)을 참고한다. 아래 계약 설명의 후속 과제는 실데이터 전체 연결에 관한 것이다.

갱신일: 2026-10-16. 요청·결과·경로 계약과 [OS 자원 제한](RESOURCE_LIMITS.md)을 구현했다. **실데이터 격리 worker의 전체 실행·승인 연결 완료는 아니다.** 기존 실행기는 여전히 같은 프로세스에서 등록 도구를 실행하며 자동 전환하지 않는다.

## 단계별 구현 순서

1. **완료:** 로컬 요청·결과 계약, 허용 경로·자원 상한 사전 검사, 합성 테스트.
2. 진행 중: [AppContainer 호환성 검사](APPCONTAINER_PROBE.md). 후속 사용자 실행에서 Python·네이티브 라이브러리·합성 Pipeline·CSV·그림 생성 및 파일 접근 제한을 확인했다. 외부 연결은 접근 거부, 로컬 연결은 timeout으로 OS 차단 확인이 남았다. 전후 정상 연결 대조·서버 관찰·토큰 capability·읽기 전용 예외 조회를 보완했으며 실제 재검증 전이다.
3. 합성 범위 확인: [Job Object 자원 제한](RESOURCE_LIMITS.md)·경과 시간/취소 감시·전체 종료 구현, AppContainer+Job 합성 호환성 실측 및 고정 합성 EDA 등록 도구의 실제 정상 실행 완료. 실데이터 연결은 남아 있다.
4. 합성 범위 구현: 기존 실행기의 정확한 승인·예약과 요청 식별값 결합, 부모의 결과 검증·완료 등록. 실데이터의 보호된 staging·원본 검사는 별도 구현·검증한다.
5. 예정: 실데이터 승인 화면·CLI와 통합·격리 검증. 차단을 실제로 강제할 수 없으면 실데이터 실행 비활성 유지.

2단계의 후속 진단으로 [WFP 수집 도구](WFP_DIAGNOSTIC.md)를 추가했다. 고유 ETW 세션·별도 동의·시간 제한·종료 실패 기록을 구현했으며 실제 수집은 아직 실행하지 않았다. 수집 완료만으로 로컬 차단을 승인하거나 3단계 완료로 취급하지 않는다.

관리자 권한·계정/ACL·방화벽 설정 변경이 필요하면 별도로 사용자에게 승인을 요청한다. Windows Sandbox를 매번 켜거나 Python을 반복 설치하는 방식으로 고정하지 않는다. AppContainer의 Python·라이브러리 호환성을 아직 보장하지 않으며 실험 결과로 격리 수단을 확정한다.

## 파일과 역할

| 파일 | 역할 |
| --- | --- |
| src/agents/worker_contract.py | WorkerLimits·WorkerRequest·WorkerResult, 엄격한 로컬 JSON 계약 |
| src/agents/worker_paths.py | 신뢰하는 WorkerPathPolicy와 로컬 경로 사전 검사 |
| tests/agents/test_worker_contract.py | 임시 합성 경로·파일·JSON 계약 검증 |

이 모듈은 전처리 방법이나 SECOM·WM 설정을 변경하지 않는다. LLM·API 호출, 실제 데이터 처리, 프로세스 생성, 시스템 설정 변경을 하지 않는다.

## 요청 계약

WorkerRequest에는 작업/실행/주체/단계·동작 식별값, 원본·프로파일·계획·정책 식별값, 정확한 입력 파일·선행 폴더, 작업 출력·임시 폴더, 자원 한도를 담는다. 원본 내용·명령·모듈·자유 인자·API 키를 받지 않는다. 등록 허용 동작은 audit·EDA·분할 제안/확정·입력 준비·최종 검사·보고서다. 원본 pickle 읽기나 ingest를 자동 허용하지 않는다.

network_policy는 전처리 worker용 deny_all만 받는다. 컴퓨터 전체 인터넷 차단을 뜻하지 않는다. 로컬 LLM과 API 연결 모듈은 별도 역할이며 이 worker 계약의 원본 읽기 권한을 공유하지 않는다. 문자열 정책은 아직 실제 네트워크 차단이 아니며 OS 강제는 후속 단계다.

WorkerLimits의 기본 요청은 벽시계 300초·메모리 2048MiB·프로세스 1개다. 데이터 크기에 맞게 관리자가 별도 상한을 정하고 요청이 상한을 넘으면 거부한다. 현재 정수 범위 검사는 실제 시간 초과 종료·메모리 제한을 수행하지 않는다.

정수 검사와 별도로 WindowsJob에 전달한 한도는 OS Job 설정·경과 시간 감시로 적용된다. 사용자 값은 그대로 사용하며 새 운영 프로파일·자동 상한 조정은 추가하지 않았다. 실데이터 WorkerRequest→OS 실행의 승인 결합은 후속 단계다.

request_id는 경로·자원 한도·네트워크 정책까지 포함한 요청 JSON의 SHA-256이다. 같은 작업 ID라도 내용이 바뀌면 다른 요청이다. 이 값은 인증 서명이나 승인 증명이 아니다. 향후 승인 범위에 이 식별값을 묶고 원본·설정 실체와 대조한 뒤 예약·실행해야 한다. IPC의 actor_id 자체를 사용자 인증으로 신뢰해서는 안 된다.

## 경로 정책

WorkerPathPolicy는 **신뢰하는 관리자 코드**가 주입한다. 요청 JSON이나 LLM이 허용 루트를 늘릴 수 없다.

- read_roots: 승인한 입력·선행 산출물의 읽기 영역.
- output_root: 새로운 worker 산출물의 작업 영역.
- scratch_root: 작업별 임시 영역.
- protected_roots: 승인 DB·비밀 등 읽기/쓰기에서 제외할 영역.

읽기·출력·임시·보호 영역을 구분하고 쓰기 루트는 읽기/보호 루트와 겹치지 않게 한다. 한 attempts 상위 폴더 전체를 동시에 읽기·쓰기 루트로 지정하지 않는다. 향후 관리자가 검증된 선행 attempt만 읽기 영역으로 주고, 별도 staging 영역의 새 결과를 검사해 완료 등록하는 방식으로 연결해야 한다.

입력은 존재하는 절대 로컬 경로만 허용한다. 상대 경로, 상위 이동, UNC/정규화 후 네트워크 경로, ADS, Windows 예약 이름, 링크·junction/reparse 항목과 하드 링크 입력을 거부한다. 폴더명 문자열 접두사가 아니라 경로 계층으로 소속을 판정한다. 보호 폴더를 포함한 상위 폴더 전체를 읽는 요청도 거부한다.

출력·임시 경로는 관리자가 미리 생성한 **빈 작업 하위 폴더**여야 한다. 루트 자체나 기존 결과 폴더는 거부한다. 경로 검사는 파일 생성·삭제·권한 변경을 수행하지 않는다.

```python
# paths와 maximum은 신뢰하는 관리자 코드가 구성한다.
# request는 승인 결합 전의 로컬 계약이며 아래 호출로 실행되지 않는다.
request.check_policy(paths, maximum)
payload = request.to_json()  # 로컬 IPC 전용. LLM에 전달하지 않는다.
```

**남은 한계:** 경로 검사 후 바꿔치기(TOCTOU), 허용 폴더 내부의 링크·파일 전체 검사, OS ACL, 보호된 요청 전달, 허용 런타임/라이브러리 접근, 프로세스의 실제 파일·네트워크 사용 통제는 아직 구현하지 않았다. Python 검사를 통과했다는 이유로 보안 격리가 완료됐다고 표현하지 않는다. 전처리 도구의 기존 파일 내용 검증과 산출물 검증도 계속 필요하다.

## 결과 계약

WorkerResult는 task_id와 request_id에 결합한다. 성공/입력 차단/실행 장애/취소/시간 초과/자원 초과를 고정 상태·코드로 구분한다. 원문 예외·stdout·stderr·절대 경로를 받지 않으며 산출물 참조는 승인된 상대 형식만 허용한다. 실패 결과는 완료 산출물 참조를 등록하지 않는다. 부분 결과는 관리자 정책에 따라 미완료로 보존할 후속 범위다.

**succeeded는 worker가 성공 종료했다고 보고한 상태일 뿐**이다. 부모 실행기가 결과의 요청 결합·내용·파일 정합성을 다시 검사한 뒤에만 기존 완료 표식·DB 커밋을 처리한다. 악의적 worker의 자체 성공 주장을 신뢰하는 구조로 연결하지 않는다.
