## 1. 목적과 범위

SECOM 센서 기반 위험 대상 선별에 WM-811K 웨이퍼맵의 공간적 결함 패턴 진단 과제를 추가한다. 센서 모델은 후속 확인 대상 선별을 연구하고, 맵 모델은 검사 결과가 확보된 이후의 패턴 분류·분석을 연구한다. SECOM 센서의 실제 수집 공정과 검사 이전 사용 가능 시점은 공개 데이터만으로 확정하지 않는다.

WM-811K는 다이별 검사 결과를 표현한 맵이므로 **EDS 이전 2차 예측 데이터로 취급하지 않는다**. EDS 이전 예측으로 확장하려면 해당 시점에 확보되는 광학 검사·계측 데이터와 이후 검사 결과가 필요하다.

두 공개 데이터셋에는 동일 웨이퍼를 연결할 대응 관계가 제공되지 않는다. 초기 모델 개발은 독립된 학습·평가와 공통 결과 보고로 수행한다. 별도로 준비하는 가상 연결 데모는 데이터 전달·결과 표시 흐름 검증으로 한정하며 실제 대응 관계와 구분해 표시한다. 임의 행 매칭을 실제 데이터로 취급하거나 두 모델 Recall을 단순 합산·곱셈해 통합 불량 감소율을 주장하지 않는다.

### 결과 역할과 시나리오 — 2026-10-09 표현 정리

- **1차:** 센서 모델의 양성은 위험 대상 선별이며 실제 불량 확정이 아니다. 음성도 기본 검사 생략이나 출하 승인을 뜻하지 않는다.
- **2차:** 웨이퍼맵 패턴과 불확실성을 제공해 검토 우선순위·추가 검사 권고를 지원한다. `None`을 이유로 센서 경고를 자동 해제하거나 정상으로 재확정하지 않는다.
- **주 시나리오:** 미검 우선의 과거 OOF Recall 목표 90%. 자동 패턴 진단 흐름을 구상하되 선별 부담과 맵 확보에 필요한 실제 검사 비용은 별도로 고려한다.
- **부담 비교 시나리오:** OOF Recall 목표 80%. 사람이 검토하는 운영 가정에서 선별 부담을 비교하며, 현장 처리 용량에 맞는 값이라고 주장하지 않는다.
- 이번 변경은 표현과 역할 정의에 한정한다. 기존 SECOM 코드·설정·실험 결과, 담당별 소유권과 독립 평가 기준은 유지한다. 최종 문턱·통합 모델 동결이나 WM 학습 완료를 뜻하지 않는다.

### 1.1 분석 목표

| 목표 | 분석 질문 | 확인할 결과 |
| --- | --- | --- |
| 공간 패턴 분류 | 웨이퍼맵에서 9종 패턴을 구분할 수 있는가? | Validation/Test Macro-F1, 클래스별 Recall·F1 |
| 희소 패턴 성능 | Near-Full·Donut·Scratch 등을 놓치는 조건은 무엇인가? | 클래스별 지원 건수·오류, 가중치 적용 전후 비교 |
| Lot 일반화 | 학습에 없던 Lot에도 분류 성능이 유지되는가? | Lot 비중첩 평가와 Lot·맵 크기별 오류 분석 |
| 전처리 영향 | 해상도·증강이 Scratch 같은 얇은 패턴을 훼손하는가? | 원본/변환 비교, 불량 마스크 보존, Validation 성능 |
| 모델 효율 | 작은 CNN 대비 ResNet18의 성능 개선이 비용 증가에 비례하는가? | 동일 조건의 Macro-F1·추론 시간·최대 메모리 |
| 검토 대상 선별 | 낮은 점수의 맵을 검토 대상으로 보내면 자동 분류 오류가 줄어드는가? | 검토 비율과 자동 분류 대상의 오류를 함께 평가 |

분석 단위는 **웨이퍼맵 1건**, 입력은 공간 배열, 정답은 패턴 라벨이다. 최종 산출물은 분류 모델, 클래스별 성능·오류 보고서, 데이터·전처리 버전과 재현 가능한 추론 묶음이다. 패턴과 공정 원인의 관계는 분석 가설로 다루며 원인 확정으로 해석하지 않는다.

## 2. 역할 분담과 소유권

| 영역 | 담당 | 책임과 산출물 |
| --- | --- | --- |
| 기존 SECOM 전처리·분석 | 이종수 | 기존 데이터 병합·EDA·split·오류 및 drift 분석 유지 |
| 기존 SECOM ML | 양현승 | 기존 V2 모델·시간순 평가·문턱·저장·추론 업무 유지 |
| **맵 전처리 에이전트** | **양현승** | 원본 확보·출처 기록, 맵·라벨 검사, 미라벨 분리, 중복·Lot 분할, 캐시·Dataset·변환, 실행 로그 |
| **WM 딥러닝** | **이종수** | 작은 CNN·ResNet18, 학습 루프, 불균형 비교, 다중 분류 평가, 모델 저장·추론, Model Card |
| 데이터·모델 계약 | 공동 | 클래스 매핑, split 정책, 입력 변환, 평가 기준, 검토 대상 판정 방식 확정 |
| 최종 평가 | 공동 | 모델·전처리·판정 설정 동결 후 Test 평가 및 결과 해석 |

양현승은 데이터 생성 경로와 전처리 코드를, 이종수는 WM 모델·학습·평가·추론 코드를 소유한다. 이종수가 입력 크기·증강 변경을 제안하면 양현승이 변환 코드에 반영하고 새로운 버전을 발급한다. split은 모델 결과에 맞춰 변경하지 않는다.

기존 SECOM 업무와 추가 업무를 구분해 기록한다. 초기 범위는 지도학습 baseline 두 개로 한정해 양쪽 담당자의 기존 작업과 새 작업이 과도하게 겹치지 않도록 한다.

## 3. 전체 구조

```text
SECOM 원본 센서
  → 센서 전처리·분석 [이종수]
  → SECOM ML 학습·평가·추론 [양현승]
  → 센서 기반 위험 점수·별도 평가 결과

WM-811K 원본 맵
  → 맵 전처리 에이전트 [양현승]
      수집 → 검사 → Lot 분할 → 캐시·Dataset → 변환
  → WM 딥러닝 [이종수]
      작은 CNN → ResNet18 비교 → 모델 동결 → Test 평가
  → 9종 패턴·클래스별 점수·검토 대상·별도 평가 결과

각 결과 → 공통 보고서 [공동]
```

공통 보고서는 각각의 데이터 범위와 성능을 표시한다. 공개 데이터 단계에서 두 결과를 같은 웨이퍼의 실제 순차 판정처럼 표시하지 않는다. 가상 연결 데모의 역할 흐름은 `센서 위험 선별 → 검사맵 확보 가정 → 패턴 진단 → 검토·추가 검사 권고`이며, 맵 부재·잘못된 입력·불확실한 결과를 정상 판정으로 치환하지 않는다. 이 흐름의 구현·검증은 별도 작업이다.

라이선스 표기는 위 Kaggle 배포 페이지에 표시된 값을 기록한 것이다. 프로젝트 코드·SECOM 데이터의 라이선스와 구분한다. 데이터 출처와 원 논문은 보고서·Model Card에 함께 기록하며, 실제 확보한 파일의 버전·해시·다운로드 시점도 보존한다. 파일 내부 배포 안내가 있으면 그 내용을 별도 기록한다.

현재 문서는 공개 페이지와 논문에 근거한 설계이며 **원본 파일 다운로드·로드·EDA를 완료했다는 뜻이 아니다**. Lot 수·파일 크기·객체 구조는 확보한 배포본과 대조한다. 기존 SECOM 데이터의 출처·정보는 [README 데이터 설명](../../README.md#데이터와-그래프)에서 관리한다.

### 4.2 규모와 라벨

| 구분 | 공개 데이터의 기대 건수 | 초기 사용 |
| --- | ---: | --- |
| 전체 | 811,457 | 구조·품질 검사 |
| 라벨 있음 | 172,950 | 지도학습 Train / Validation / Test |
| 미라벨 | 638,507 | 별도 보존, 초기 지도학습·평가에서 제외 |

실제 확보한 배포본의 건수·컬럼·클래스 분포는 양현승의 검사 결과로 확정한다. 공개 기대값과 다르면 차이와 제외 사유를 기록한다. 미라벨을 `None`으로 치환하지 않는다.

패턴 클래스는 `None`, `Center`, `Donut`, `Edge-Loc`, `Edge-Ring`, `Loc`, `Near-Full`, `Random`, `Scratch`의 9종이다. `None`은 특정 불량 패턴 없음이며, 최종 양품 판정과 같지 않다. 원본의 빈 라벨과 명시적 `None` 클래스는 별도 처리한다.

초기 목표는 웨이퍼 단위 9종 분류다. 다이 단위 불량 위치는 입력 맵에 이미 포함되므로 별도의 위치 검출·분할 모델을 기본 범위에 넣지 않는다. 혼합 패턴과 미지 패턴은 9종 단일 분류의 한계로 기록한다.

### 4.3 데이터 항목과 활용

아래는 읽기 검사에서 확인할 주요 원본 항목이다. 원본 컬럼과 실제 값의 형태를 보존한 뒤 6절의 canonical manifest로 변환한다. 기본 6개 항목은 [AWS의 WM-811K 데이터 처리 예제](https://github.com/aws-samples/amazon-ec2-nice-dcv-semiconductor-wafer-data/blob/master/README.adoc)에서도 확인할 수 있으며, Kaggle pickle의 세부 표기·중첩 구조는 실제 배포본으로 검증한다.

| 원본 항목 | 정보·예상 형태 | 이번 분석에서의 사용 |
| --- | --- | --- |
| `waferMap` | 웨이퍼의 가변 크기 2차원 배열. 각 위치는 다이 상태 또는 웨이퍼 밖 영역 | CNN 입력의 불량·유효 다이 마스크 생성 |
| `dieSize` | 원본의 다이 규모 관련 수치 metadata. 구체 의미·단위는 원본 정의와 배열을 대조해 확인 | EDA와 맵 규모별 오류 분석. 초기 CNN의 별도 수치 입력으로 사용하지 않음 |
| `lotName` | 생산 Lot 식별 문자열 | Lot 단위 분할·누수 검사·그룹별 분석. 모델 feature에서 제외 |
| `waferIndex` | Lot 내부 웨이퍼 식별·순서 metadata | Lot과 함께 ID 검사·추적. 단독으로 전역 유일 ID라 가정하지 않음 |
| `trianTestLabel` / `trainTestLabel` | 배포본별 표기를 확인할 원본 Training/Test 구분. 배열·빈 값 여부도 검사 | 원본 분할 이력 보존. 기본 Lot 분할과 별도 관리하며 모델 feature에서 제외 |
| `failureType` | 패턴 이름 또는 빈 라벨. 중첩 배열 여부 확인 | 9종 정답으로 정규화. 빈 라벨은 미라벨로 유지 |

`waferMap`의 기대 값은 `0=웨이퍼 밖`, `1=정상 다이`, `2=불량 다이`다. 가로·세로 크기는 배열의 `shape`에서 계산한다. `dieSize`를 이미지 해상도나 물리 면적으로 임의 변환하지 않는다. Lot·웨이퍼 번호를 실제 공정 시간으로 해석하지 않는다.

파생 EDA 항목은 맵 크기, 유효 다이 수, 불량 다이 수, 불량 다이 비율, Lot별 샘플 수다. 불량 다이 비율은 `불량 다이 수 / 유효 다이 수`로 계산하며 유효 다이가 없는 맵은 오류 대상으로 기록한다.

### 4.4 패턴 정보와 클래스 불균형

| `Edge-Loc` | 가장자리 일부 영역에 집중 | 5,189 |
| `Edge-Ring` | 가장자리를 따라 형성된 고리 | 9,680 |
| `Loc` | 일부 국소 영역에 집중 | 3,593 |
| `Near-Full` | 거의 전체 영역에 분포 | 149 |
| `Random` | 무작위로 흩어진 불량 | 866 |
| `Scratch` | 선·긁힘 형태의 불량 | 1,193 |
| 합계 | 라벨 데이터 | 172,950 |

`None`이 약 85.2%를 차지하므로 다수 클래스만 예측해도 Accuracy가 높게 나올 수 있다. Macro-F1·클래스별 Recall을 주요 지표로 정하고, 희소 클래스의 평가 표본 수를 항상 함께 표시한다.

## 5. 맵 전처리 에이전트 — 양현승

### 5.1 책임 범위

실행 그래프·승인·재개·LLM provider·외부 추적의 기초 구조는 [에이전트 기초 설계](../agents/DESIGN.md#목표와-범위)를 따른다. 전처리 코어를 먼저 완성하고 에이전트가 이를 호출한다.

에이전트는 정해진 수집·검사·분할·변환 작업을 실행하고 실패·재시도·산출물 위치를 기록한다. 실제 데이터 변환과 분할은 버전이 고정된 코드가 수행한다. 에이전트가 실행마다 라벨·제외 기준·split·증강을 임의로 바꾸지 않도록 설정 파일로 관리한다.

예정 작업 단위는 `ingest → audit → split → prepare → validate_contract`다. 실패한 단계의 부분 결과는 완료 산출물로 등록하지 않고, 동일 원본·설정의 재실행 여부는 해시로 확인한다.

### 5.2 분할과 누수 방지

1. 라벨 데이터의 ID·중복·Lot을 검사한 뒤 split을 생성한다.
2. 기본 평가는 **Lot이 겹치지 않는 분할**로 한다. Train/Validation/Test는 70/15/15를 목표로 하되 Lot 보호와 희소 클래스 때문에 실제 비율은 달라질 수 있다.
3. 동일 맵 중복은 분할 전에 처리하고 보존·제외 기준을 기록한다. 중복을 보존하는 경우 같은 split에 묶는다.
4. 각 split의 클래스별 지원 건수를 확인한다. 희소 클래스가 평가 구간에 없으면 그 클래스 성능을 평가 가능하다고 표시하지 않는다. 분할 불가능 조건은 학습 전에 공동 검토한다.
5. 원본 train/test 표식은 metadata로 보존한다. 원본 분할을 따르는 비교가 필요하면 별도 프로토콜로 실행하고 Lot 분할 결과와 혼용하지 않는다.
6. 실제 timestamp가 없다면 시간순 일반화 성능을 주장하지 않는다. Lot 이름·행 순서를 시간으로 대체하지 않는다.
7. 증강·샘플링은 split 이후 Train에만 적용한다. Validation/Test는 원래 분포를 유지한다.
8. 추후 미라벨 학습에서도 평가용 Lot과 중복 맵을 학습에서 제외한다.

### 5.3 입력 변환과 메모리

구현 순서·정확한 변환 규칙·분할 가능성 검사·캐시 구조는 [전처리 상세 설계](PREPROCESSING_DESIGN.md)를 따른다. 증강은 우선 비활성 baseline부터 시작하고 아래 후보를 후속 비교한다. 동일 맵 연결로 여러 Lot이 하나의 큰 그룹이 될 수 있으므로 실제 중복 검사 없이 분할 가능성을 확정하지 않는다.

- 원본 맵은 작은 정수 배열로 보존하고 맵 내용 해시를 기록한다.
- 초기 CNN 입력은 **불량 다이 마스크 + 유효 다이 마스크의 2채널**로 제안한다. 정상 다이와 웨이퍼 밖 영역을 구분할 수 있다.
- 입력 해상도는 우선 `128 × 128`로 제안하고 Validation에서 Scratch 보존과 처리 비용을 확인한다. 최종 값은 공동 확정한다.
- 종횡비 유지, 최근접 보간, padding을 사용하고 변환 후 범주·마스크 정합성을 검사한다. 축소 시 희소 불량이 사라지는 정도도 기록한다.
- 초기 증강은 Train의 90도 단위 회전·좌우/상하 반전을 후보로 한다. 방향 의미가 보존되는지 확인한 뒤 적용한다. 맵의 절단·blur·임의 삭제는 초기 기본값에서 제외한다.
- 전체 80만 맵을 확대된 float tensor로 한 번에 적재하지 않는다. 원본 읽기의 최대 메모리를 확인하고, 변환 캐시를 shard로 보존한 뒤 Dataset이 배치 단위로 로딩한다.

이종수는 첫 배치의 shape·dtype·채널 의미·라벨 범위, manifest와 캐시 대응, split별 Lot 및 중복 비중첩을 확인한 뒤 학습을 시작한다. 배포본 클래스 순서에 의존하지 않고 전달된 매핑을 사용한다.

## 7. WM 딥러닝 — 이종수

### 7.1 사용 예정 모델과 선정 이유

| 모델 | 우선순위·목적 | 선정 이유와 초기 방안 |
| --- | --- | --- |
| 다수 클래스 예측 기준선 | 필수 평가 기준 | 불균형 데이터에서 Accuracy의 효과를 확인. Train의 최빈 클래스 고정 예측 |
| 작은 CNN | 1차 필수 구현 | 고리·선·국소 불량 같은 공간 패턴을 단순 구조로 학습. Conv 블록 → Global Average Pooling → 9종 출력 |
| ResNet18 | 2차 필수 비교 | 작은 CNN보다 깊은 특징 추출의 효과를 비교. 첫 convolution을 2채널에 맞추고 출력층을 9종으로 구성 |
| MobileNetV3-Small | 후속 선택 | 모델 크기·처리 시간이 병목일 때 정확도와 비용의 균형을 비교 |

초기 CNN·ResNet18은 무작위 초기화로 비교한다. 사전학습 가중치를 추가하면 2채널 입력 변환 방법과 학습 조건을 별도 실험으로 기록한다. Transformer·준지도학습·생성 모델은 baseline 이후 확장 후보로 남긴다.

CNN 입력은 제안 기준 `2 × 128 × 128`, 출력은 9종 logits다. 최종 모델은 Validation Macro-F1만 단독으로 보지 않고 희소 클래스 Recall, seed별 변동과 추론 비용을 함께 검토해 선정한다. Test 성능을 보고 모델을 선택하지 않는다.

### 7.2 학습과 평가

- 동일한 데이터·split·입력 변환·학습 예산으로 CNN과 ResNet18을 비교한다.
- 기본 Cross Entropy와 Train 빈도 기반 class-weighted Cross Entropy를 비교한다. 가중치·샘플링을 동시에 강화하는 실험은 초기 범위에서 제외한다.
- AdamW를 초기 optimizer 후보로 두고 learning rate·batch size·epoch 상한·early stopping은 설정으로 관리한다. 실제 GPU 메모리·처리 시간을 측정한 뒤 값을 확정한다.
- checkpoint 선택과 early stopping은 Validation Macro-F1을 사용한다. 클래스별 Recall도 함께 확인한다.
- 지표는 Macro-F1, 클래스별 Precision·Recall·F1·지원 건수, 혼동행렬, Accuracy, 학습 시간, 추론 시간과 최대 메모리다.
- 작은 CNN·ResNet18 baseline을 확보한 뒤 채택 후보는 여러 seed로 변동을 확인한다. 반복 실험은 최종 Test를 사용하지 않는다.
- 클래스별 점수와 최대 점수를 출력한다. 낮은 신뢰도의 검토 기준은 Validation에서 선택하고 Test 전에 동결한다. softmax 점수를 보정된 불량 확률이라고 해석하지 않는다.
- 검토 기능은 검토 비율과 자동 분류 대상의 오류를 함께 평가한다. 검토 대상으로 빠진 샘플을 정답 처리하지 않는다.
- `1 - P(None)`은 패턴 존재 점수로만 다룬다. SECOM 불량 확률과 같게 해석하거나 SECOM 문턱을 재사용하지 않는다.

## 8. 구현 모듈과 저장 구조 제안

기존 코어는 표 형태·이진 분류 계약을 유지하고, 이미지·다중 분류 경로를 별도 패키지에 둔다. 기존 `config.json`의 데이터 Profile을 WM 설정으로 교체하지 않는다.

| 단계 | 담당 | 완료 기준 |
| --- | --- | --- |
| 1. 목표·데이터 계약 | 공동 | 분류 단위·패턴 의미·검사 시점·클래스 매핑·분할 정책 합의 |
| 2. 데이터 확보 | 양현승 | Kaggle 파일·출처·라이선스·버전·해시 기록 |
| 3. 품질 검사 | 양현승 | 객체·컬럼·맵 값·라벨·Lot·중복·제외 내역 검사 |
| 4. EDA | 양현승 주관, 이종수 검토 | 클래스·맵 크기·Lot 분포, 대표 패턴과 희소 클래스 사례, 처리 메모리 보고 |
| 5. split 생성·봉인 | 양현승 | Lot·중복 누수 검사 통과, 클래스별 지원 건수와 split manifest 확정 |
| 6. 전처리·Dataset 전달 | 양현승, 이종수 인수 | 마스크·해상도·Train 증강·배치 로딩 검사, 변환 설정·첫 배치 전달 |
| 7. 기준선·작은 CNN | 이종수 | 다수 클래스 기준선과 CNN Validation 결과, 저장·복원·별도 추론 연결 |
| 8. ResNet18·불균형 비교 | 이종수 | 동일 계약·학습 예산의 모델·loss 가중치 비교 |
| 9. 오류 분석·개발 개선 | 이종수 주관, 양현승 전처리 지원 | 클래스·Lot·맵 크기별 오류, Validation 기반 해상도·증강·검토 기준 검토 |
| 10. 전처리·모델 동결 | 공동 | 모델·클래스 매핑·변환·검토 기준·평가 방법 확정 |
| 11. 최종 Test·보고 | 공동 | 동결 모델로 평가, 클래스별 결과·한계·Model Card 작성 |

진행 흐름은 `목표 확정 → 수집 → 품질 검사 → EDA → Lot 분할 → 전처리 → CNN → ResNet18 비교 → 오류 분석 → 동결 → Test·보고`다. 개발 개선은 Train/Validation에 한정하고, 변환이 변경되면 데이터 계약 버전과 영향을 받은 실험을 함께 갱신한다.

학습 결과를 보고 Test를 반복 최적화하지 않는다. 성능의 수치 목표는 데이터 검사와 Validation baseline을 확인한 뒤 공동 결정하고 Test 전에 기록한다. 구현 완료와 현장 적용 가능 판정은 구분한다.

검증은 manifest·캐시 정합성, Lot·중복 비중첩, 변환의 마스크 보존, seed·버전 재현성, 저장 전후 추론 동일성, 별도 프로세스 복원과 잘못된 입력의 명확한 실패를 중심으로 수행한다.

## 10. 이후 실제 연계에 필요한 조건

실제 2단계 시스템으로 연결하려면 같은 웨이퍼의 `lot_id`, `wafer_id`, 센서 수집 시점, 검사 시점, 맵과 최종 결과를 확보해야 한다. 1차 판정이 2차 검사 대상에 미치는 영향과 검사를 받지 않은 샘플의 평가 방법도 정의해야 한다.

1차 선별 대상만 2차로 보내는 경로는 1차 미검을 복구할 수 없다. 현재 2차의 역할은 패턴 진단과 검토 지원이며 양성 일치를 요구하는 출하 판정기가 아니다. 향후 2차로 경고를 해제하는 정책을 도입한다면 추가 미검을 포함해 전체 FN·FP, 후속 검사 부담과 처리 시간을 실제 연결 데이터에서 평가해야 한다. 공개 데이터 단계에서는 이 정책의 성능을 추정하지 않는다.
